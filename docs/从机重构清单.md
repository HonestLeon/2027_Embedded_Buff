## 一、从机要干什么（一句话拆解）

```
收 CAN(0x161) ──► 按灯板号判断是否与我有关 ──► 切状态
      │                                            │
      │                                    ① 休眠(全灭)    state 1
      │                                    ② 待激活(特殊灯效+箭头流动) state 2
      │                                    ③ 已激活(环数显示+进度条)   state 3
      │                                    ④ 全激活(全亮)             state 4
      ▼
弹丸击打(EXTI ×10) ──► 判环数 ──► 上报 CAN(0x160) 或 上报"打错复位"
```

| CAN1 位率 | **1Mbps**（P=3/BS1=10TQ/BS2=3TQ）✓，且 `AutoRetransmission`/`AutoBusOff` = **ENABLE**（本次改动）✓ |
| CAN2 | 保留（100kbps，从机不用但 `bsp_can.c` 主从共用）✓ |
| 中断入口 | 6 EXTI + 6 DMA + CAN1_RX0 + CAN2_RX0 + TIM6_DAC ✓ |

### 以下为原操作清单（留档备查）

### 2.1 加回击打检测输入（10 引脚 + 6 中断）

| 项 | 值 |
|---|---|
| 引脚 | **PA1~PA5、PC6~PC10** → 全部 `GPIO_EXTIx`，触发沿 **Rising_Falling**（实测极性后再收敛） |
| Pull | **No pull-up and no pull-down**（硬件已有 1kΩ 串阻 + 10kΩ 上拉 + 10µF 消抖） |
| User Label | **KEY1 ~ KEY10**（与老从机 `RDET1~10` 引脚一一对应） |
| NVIC | `EXTI1/2/3/4_IRQn`、`EXTI9_5_IRQn`（PA5+PC6~9）、`EXTI15_10_IRQn`（PC10），抢占优先级 **3** |

> 老从机 `main.h` 的 RDET 映射（已核对，与新板一致）：
> RDET1~5 = PA1~PA5，RDET6~10 = PC6~PC10。

### 2.2 加回其余灯带（TIM4 全通道 + TIM3 的 CH2/CH4）

PWM 参数与主机完全一致：`PSC=2`、`ARR=34`、PWM1、Pulse=0、极性 High、**Direction = Memory To Peripheral**、
PeriphInc 不勾 / MemInc 勾 / 双方 Half Word / Mode=Normal / Priority=Low。

| 通道 | 引脚 | 老从机用途（`WS2812.h` 注释） | 灯数（**待实测复核**） |
|---|---|---|---|
| TIM3_CH1 | PA6 | `LED_ROAD_3` "上" | 87 |
| TIM3_CH2 | PA7 | `LED_ROAD_2` "中" | 262 |
| TIM3_CH4 | PB1 | `LED_ROAD_4` "灯臂" | 320 |
| TIM4_CH1 | PB6 | `LED_ROAD_5` "侧灯臂" | 120 |
| TIM4_CH2 | PB7 | `LED_ROAD_1` "下" | 92 |
| TIM4_CH3 | PB8 | **老从机从未驱动** | 待核实是否接灯带 |

各通道需 1 条 DMA 流（**只留实际接线的**）：

| 通道 | DMA 流 | 对应 NVIC |
|---|---|---|
| TIM3_CH2 | DMA1_Stream5 | `DMA1_Stream5_IRQn`（抢占 5） |
| TIM3_CH4 | DMA1_Stream2 | `DMA1_Stream2_IRQn` |
| TIM4_CH1 | DMA1_Stream0 | `DMA1_Stream0_IRQn` |
| TIM4_CH2 | DMA1_Stream3 | `DMA1_Stream3_IRQn` |
| TIM4_CH3（若接灯带） | DMA1_Stream7 | `DMA1_Stream7_IRQn` |

> ⚠️ **务必逐条核对 Direction = `Memory To Peripheral`**。配成 `Peripheral To Memory` 会：
> ①CCR 拿不到数据（灯全黑）；②失控 DMA 沿 CCR 地址递增写穿 TIM3 寄存器块，
> 砸坏 TIM4/TIM5/**TIM6（1ms 调度）**/TIM7 → 调度失效。判据见 `CubeMX裁剪说明.md` 第五节。

### 2.3 保留不动

TIM6（1ms 调度）、CAN1（PA11/PA12，1Mbps，与主机一致）、RNG、拨码 PD2/PB3/PB4、板卡 ID PC11/PC12/PB9、SWD、HSE。
CAN2 从机用不到 → 可以删（老从机虽配了 CAN2，但代码里没用）。

### 2.4 波特率

**CAN1 = 1Mbps**（与主机完全一致，参数 `P=3 / BS1=10TQ / BS2=3TQ`）——已由旧从机生成代码确认，
主机对接测试已通过。

## 三、代码改动清单（逐文件）

### 3.1 `config/config_board.h`

```c
#define BOARD_ROLE_MASTER  0        /* 从机构建 */
```
- 拨码极性沿用实测结论（`*_ACTIVE_LEVEL = 1`：OFF/下=低、ON/上=高）；
- `TEST_TRIGGER_USE_SW2` / `DEBUG_TEST_MODE`：灯带通道扫描仍可用（从机有 5~6 条灯带，**开工第一件事就是扫描定位**）。

### 3.2 `config/config_ws2812.h` + `bsp/bsp_ws2812.c`（**关键**）

按从机实际接线重填灯带表与缓冲（主机版现在只有 1 条，从机要 5~6 条）：

```c
#define WS2812_STRIP_TBL { \
    { &htim3, TIM_CHANNEL_1, <实测灯数> },   /* 索引0 = 老 LED_ROAD_3 "上"   */ \
    { &htim3, TIM_CHANNEL_2, <实测灯数> },   /* 索引1 = 老 LED_ROAD_2 "中"   */ \
    { &htim3, TIM_CHANNEL_4, <实测灯数> },   /* 索引2 = 老 LED_ROAD_4 "灯臂" */ \
    { &htim4, TIM_CHANNEL_1, <实测灯数> },   /* 索引3 = 老 LED_ROAD_5 "侧灯臂"*/ \
    { &htim4, TIM_CHANNEL_2, <实测灯数> },   /* 索引4 = 老 LED_ROAD_1 "下"   */ \
    { &htim4, TIM_CHANNEL_3, <实测灯数> },   /* 索引5 = 老从机未用           */ \
}
#define WS2812_STRIP_NUM   <条数>
```
缓冲同步补回（每条一对 `s_ccrN/s_rgbN`），并核对 RAM：
`Σ(灯数×24+90)×2B`，例如 5 条 881 灯 ≈ **43KB**（F405 主 SRAM 112KB 够，但别放 CCM——DMA 访问不到）。

> **开工第一步必须先做通道扫描**（`DEBUG_TEST_MODE=1` + Watch `g_dbg_ws_scan_idx`）：
> ①确认每条灯带挂在哪个索引；②点数确认灯数；③记录"索引 ↔ 物理位置"对照表。
> 主机板就吃过亏：丝印与固件口径系统性错位（见 `docs/主机CubeMX配置清单.md` 0.2 节）。

### 3.3 `application/buff.c`（**换掉状态机段**）

保留（主从共享的真相源，**逐字节别改**）：
- `buff_frame_pack/parse`、`buff_send_frame`、`buff_slave_report_parse`、`buff_random_small/big`

替换（文件头已标注"主机构建专用"的那一段）为**从机状态机**：

| 状态 | 显示 | 行为 |
|---|---|---|
| `SLV_SLEEP`（老 state 1） | 5 条全灭 | 收到 `0x01` / `0x03` 进入；进入时**清 `once`**（重新武装击打） |
| `SLV_ARMED`（老 state 2） | 待激活图案 + 灯臂箭头流动 | 收到 `0x02` 进入；**只有此状态允许被击中** |
| `SLV_ACTIVATED`（老 state 3） | 环数显示 + 进度条 | 被击中时进入；**进入瞬间上报 `0x03`**（一条，不重复发） |
| `SLV_ALL_ON`（老 state 4） | 全激活外观 | 收到 `0x04` 进入（**不需匹配灯板号**） |

解码规则（老 `Decode()` 的等价物，注意两个细节）：
```c
if ([0] != 0xaa) return;
/* ① 0x03(复位) 与 0x04(全亮) 不看灯板号; 0x01/0x02 必须 [3]==BUFF_NUM || [5]==BUFF_NUM */
/* ② 大小符/颜色/round 每帧都更新: [2]→大小符, [4]→红蓝, [6]→round(已激活组数, 供进度显示) */
```

### 3.4 `application/hit_detect.c/.h`（**新增**）

老 `gpio.c` 的 EXTI 回调 → 拆成"中断只记录 + 逻辑帧判定"，并把老代码的隐式标志显式化：

```c
/* 引脚→环数 标定表(2025 老代码口径, ⚠ RDET9/10 待实测复核, 见第五节) */
static const struct { uint16_t pin; GPIO_TypeDef *port; uint8_t circle; } hit_map[] = {
    { KEY1_Pin,  KEY1_GPIO_Port, 10 }, ... { KEY8_Pin,  KEY8_GPIO_Port,  3 },
    { KEY9_Pin,  KEY9_GPIO_Port,  1 },     /* ⚠ 老代码写的 1(疑为 2) */
    { KEY10_Pin, KEY10_GPIO_Port, 1 },
};

typedef enum { HD_ARMED, HD_FIRED, HD_LOCKED, HD_MISHIT } hd_state_t;
void hit_detect_on_exti(uint16_t pin);   /* EXTI 回调里调: 只记时间戳+置位 */
void hit_detect_task(void);              /* 4Hz: 查表判定 → 通知 buff 状态机 */
```

老代码的三个隐式机制要保留其**语义**（可换更清晰的实现）：
- `once` 三态：`0`=可击发 → `1`=已击发 → `2`=打错(要上报复位)，**进入休眠状态时清零**（= 重新武装）；
- `start` 锁存：老代码在第一次中断后锁 ~2 个主循环(≈400ms)内的后续中断 → 新的做法可用
  "一次激活只接受一次击打"（由 `HD_ARMED→HD_FIRED` 天然保证）+ 必要的时间去抖；
- **打错 = 中断发生在非 `ARMED` 状态**（打已激活的板、或休眠状态被击）→ 上报 `0x01`([2]) 并回休眠。

### 3.5 `application/light.c`（**图案库**）

老 `WS2812.c` 的图案函数搬过来，**标定数值一个字都别改**（逐颗数出来的）：

| 图案 | 老函数 | 说明 |
|---|---|---|
| 待激活靶面 | `Buff_Activatable(R,G,B)` | 20 段标定，见 `config_light.h` 的 `LIGHT_ARMED_SEGS` |
| 灯臂箭头流动 | `Buff_Arrowhead_Flowing` | 4 行模板 + 相位 |
| 环数显示 | `Buff_Activating(circle)` | `LIGHT_RING_MAP` 10 组 {起始,长度} |
| 全激活 | 老 state 4 只点了 2 条(值 10) | ⚠ 需确认"已激活"外观（规则图 5-23） |
| 进度条 | 老代码 4/5 条全亮(定值 10) | ⚠ **规则要求"中部灯臂按已激活组数显示 n/5"** → 新实现按 `round` 分段点亮 |

### 3.6 调度（`Core/Src/stm32f4xx_it.c`，沿用主机模板）

```c
/* 1ms: */
motor_*                        → 删除（从机无电机）
hit_detect_task();             /* 击打判定(或放 4Hz) */
bsp_can1 排空 → 解码 → 状态   /* ⚠ 见第四节: 必须 1ms 级, 不能等 4Hz */
bsp_ws2812_refresh_all();
/* 4Hz: */
从机状态机抬升/灯效动画 + light_tick() + 上报
```

### 3.7 Keil 工程

`application` Group：加 `hit_detect.c`，删 `motor.c`；`bsp` Group 不变；Include Paths 不变。

## 四、⚠️ 协议时序要求（从机必须满足，否则功能静默失效）

| 场景 | 主机发帧 | 间隔 | 要求 |
|---|---|---|---|
| 大符轮次切换 | 先 `0x01`(熄灭旧对) → 再 `0x02`(点亮新对) | **150ms** | **从机必须 1ms 级排空 CAN**，两帧都要看到；否则熄灭帧被后一帧覆盖 → 旧灯板不熄（老从机 200ms 单缓冲的固有缺陷，实测表现为"熄灭不稳定/一开始不熄灭"） |
| 打错复位 | `0x160` 上报 `[2]=0x01` | — | 主机侧"复位优先"判定，从机如实上报即可 |
| 规则上限 | "重新点亮前灯效熄灭至多 200ms" | — | 主机已取 150ms，从机不得引入额外延迟（如 200ms 阻塞） |

**结论**：从机把 `bsp_can1_pop()` 放 **1ms 节拍**里排空（只做"收帧→更新目标状态/置事件"），
灯效与状态机放 4Hz 逻辑帧。**禁止 `HAL_Delay(200)` 之类的阻塞**（老从机就是这么写的）。

## 七、协议速查

**下行（主机 → 从机，ID `0x161`）**

| [0] | [1] 命令 | [2] 大小符 | [3] 灯板号 | [4] 颜色 | [5] 第二块 | [6] 已激活组数 | [7] |
|---|---|---|---|---|---|---|---|
| `AA` | `01`熄灭 `02`点亮 `03`复位 `04`全亮 | `01`大`00`小 | 1~5（全亮/复位时可忽略） | `00`红`01`蓝 | 大符第二块 1~5 | 0~5（进度显示用） | 0 |

**上行（从机 → 主机，ID `0x160`）**

| [0] | [1] | [2] | [3] |
|---|---|---|---|
| `AA` | `03` = 我被打中 | `01` = 我打错了(需复位) | 本机灯板号 |

> ⚠️ 上行是**共用帧结构的重载**：报复位时只改 `[2]`，`[1]` 会残留上一次的 `0x03`
> —— 所以主机侧是**复位优先**判定（`buff_slave_report_parse` 已处理，从机照发即可）。
