## 一、从机要干什么（一句话拆解）

```
收 CAN(0x161) ──► 按灯板号判断是否与我有关 ──► 切状态
      │                                            │
      │                                    ① 休眠(全灭)    state 1
      │                                    ② 待激活(特殊灯效+箭头流动) state 2
      │                                    ③ 已激活(环数显示+灯臂全亮)   state 3
      │                                    ④ 全激活(全亮)             state 4
      ▼
弹丸击打(EXTI ×10) ──► 判环数 ──► 上报 CAN(0x160) 或 上报"打错复位"
```

### 3.2 `config/config_ws2812.h` + `bsp/bsp_ws2812.c` —— ✅ 完成（灯数继承老从机口径，无需实测）

灯数**只定义一次**，灯带表与 DMA 缓冲都由它推导 —— 根治"改了表忘了改缓冲"的越界：

```c
/* config_ws2812.h：口径直接继承老从机(硬件未变)，无需实测标定 */
#define WS_LED_NUM_UP         87u   /* 索引0 TIM3_CH1/PA6  老 LED_ROAD_3 上   */
#define WS_LED_NUM_TARGET    262u   /* 索引1 TIM3_CH2/PA7  老 LED_ROAD_2 中(靶面) */
#define WS_LED_NUM_ARM       320u   /* 索引2 TIM3_CH4/PB1  老 LED_ROAD_4 灯臂 */
#define WS_LED_NUM_ARM_SIDE  120u   /* 索引3 TIM4_CH1/PB6  老 LED_ROAD_5 侧灯臂 */
#define WS_LED_NUM_DOWN       92u   /* 索引4 TIM4_CH2/PB7  老 LED_ROAD_1 下   */
#define WS_LED_NUM_SPARE       0u   /* 索引5 TIM4_CH3/PB8  待核实是否接灯带   */
#define WS2812_STRIP_TBL { {&htim3,TIM_CHANNEL_1,WS_LED_NUM_UP}, ... }  /* 6 行 */
#define WS2812_STRIP_NUM     6u
```

RAM 实测（`arm-none-eabi-size` 量 `.bss`，S1 完成时）：**46,208 B ≈ 45.1KB**（老口径 881 颗；索引5=PB8 置 0 后只剩占位 3B）。
数据区共 128KB（Keil 按 Target 对话框生成的 scatter = `RW_IRAM1` 0x20000000/112KB +
`RW_IRAM2` 0x2001C000/16KB），**CCM(0x10000000) 根本不在数据区里** → 静态缓冲不可能落到
DMA 访问不到的 CCM，这条原先靠"记得别放 CCM"的口头约束可以撤销（S2 若把灯数往上改，
留意 881 颗这一档还有约 78KB 余量）。

> **灯数与映射不需要标定**（S2 已重定义为口径继承）。逐条点亮只是**排障工具**，见 [`从机灯带自检与排障.md`](从机灯带自检与排障.md)：
> 只在“某条不亮 / 段位不对 / 改过接线”时用它定位。⚠ 本板未接拨码，**只能用 `DEBUG_TEST_MODE=1` 编译期触发**"索引 ↔ 物理位置"对照表并回填上面的宏。
> （`SW2=ON` 那套触发在从机不可用）。仅当实测与老口径不符时，才回填 `WS_LED_NUM_*`。

### 3.4 `application/hit_detect.c/.h`（**新增 · ✅ S4 已落地 2026-10-10**）

老 `gpio.c` 的 EXTI 回调 → 拆成"中断只记录 + 逻辑帧判定"，并把老代码的隐式标志显式化：

```c
/* 引脚→环数 标定表(2025 老代码口径; ⚠ RDET9/10 仍需台架短接核对, 见第五节 —— 机械映射不受硬件未变影响) */
static const struct { uint16_t pin; GPIO_TypeDef *port; uint8_t circle; } hit_map[] = {
    { KEY1_Pin,  KEY1_GPIO_Port, 10 }, ... { KEY8_Pin,  KEY8_GPIO_Port,  3 },
    { KEY9_Pin,  KEY9_GPIO_Port,  1 },     /* ⚠ 老代码写的 1(疑为 2) */
    { KEY10_Pin, KEY10_GPIO_Port, 1 },
};

typedef enum { HD_ARMED, HD_FIRED, HD_LOCKED, HD_MISHIT } hd_state_t;
void hit_detect_on_exti(uint16_t pin);   /* EXTI 回调里调: 只记时间戳+置位 */
void hit_detect_task(void);              /* 4Hz: 查表判定 → 通知 buff 状态机 */
```

老代码的三个隐式机制要保留其**语义**（实现必须换，见下面的硬约束）：
- `once` 三态：`0`=可击发 → `1`=已击发 → `2`=打错(要上报复位)，**进入休眠状态时清零**（= 重新武装）；
- `start` + `start_countt`：老代码在**任意一个沿**之后把 EXTI 整体锁死约 2 个主循环(≈400ms)，
  期间所有后续沿只清标志不判定 —— 它同时干了两件事：①吞掉同一次击打的抖动/回弹，
  ②也顺带吞掉了别的板的击打；
- **打错 = 中断发生在非 `once==0 && state==2` 条件**（打已激活的板、或休眠状态被击）→ 上报 `[2]=0x01` 并回休眠。

#### ⚠️ S4 的三条硬约束（不遵守就会把一次正常击打变成"打错复位"，整轮被清）

1. **沿数不一致（已修正）**：老从机 10 路是 `GPIO_MODE_IT_FALLING`（只下降沿），而本工程最初
   误配成 `RISING_FALLING` 双边沿 → 同一次击打产生 2 个沿（击打 + 回弹），第二个沿到达时
   `HD_ARMED → HD_FIRED` 已发生，照第 3 条字面判定就会被判"打错"→ 上报 `[2]=0x01` → 主机整轮复位。
   ✅ **已落地**：`.ioc`（10 处 `GPIO_ModeDefaultEXTI`）与 `gpio.c`（2 处）均改为 `GPIO_MODE_IT_FALLING`
   （依据：老固件整季验证；两者一起改，重新生成也一致）。
   ➕ **仍建议**在软件里保留 `HD_IGNORE_MS`（50~100ms）窗内忽略同一引脚的后续沿，作为二道防线。
2. **未匹配引脚的杂散中断不得判打错**：老 `HAL_GPIO_EXTI_Callback` 的 `else` 分支是
   "任何没落进 10 个 KEY 判断的回调 → `once=2`"（`EXTI9_5` 一次给 5 个线号都调一遍回调，
   多余的那几次全靠引脚比较兜住）→ 新实现里 `pin` 不在 `hit_map[]` 内时**只清标志直接返回**。
3. **打错要能区分"同一次击打的后续沿"与"真打错"**：落地判据 = 状态非 `HD_ARMED`（或已击发）
   **且** 距上一沿 > `HD_IGNORE_MS` —— **超窗任何引脚都算打错**，窗内一律吞（同引脚回弹与
   相邻电极抖动都是杂散沿）。这与老代码"锁存期外从不看引脚、一律判打错"的语义一致。
   ⚠ 2026-10-10 验收修正：初版曾把"引脚≠上次击发引脚"设为**永久**条件 —— 后果是同一环的
   再击打永远判不进打错（台架⑩"已激活的板再被打同一环"将无上报），已移除；引脚信息仍记
   `g_dbg_hit.last_pin` 供观测。另：老 `start` 锁存 ≈400ms，新窗 100ms，**100~400ms 区间的
   第二环真击新会判打错、老被吞**（见差异表 #19）；⑩ 必须专门打"已激活的板"与"休眠的板"各一次。

另外：老代码从击发到上报走的是"主循环 200ms 一轮"，上报最快也要 0~200ms；新架构里
判定放在 4Hz 逻辑帧 → 上报最坏延迟 250ms，**比老代码还慢**。若台架发现主机响应迟钝，
把 `hit_detect_task()` 挪进 1ms 节拍（判定本身只有几个变量比较，开销可忽略）。

### 3.5 `application/light.c`（**图案库 · ✅ S6 已落地 2026-10-10，纯复刻口径**）

### 3.6 调度（`Core/Src/stm32f4xx_it.c`，沿用主机模板）

> ✅ **S3.1 已落地(2026-10-06)**：`it.c` 的 1ms 段现为 `buff_can_rx_poll()` → `bsp_ws2812_refresh_all()` → `buff_tick()`；
> ✅ **S4/S5 接线已落地(2026-10-10)**：1ms 的 `buff_tick()` = 消费 `my_ev_*` 锁存做帧触发的状态转换；
> 4Hz 帧顺序 = `hit_detect_task()` → `buff_step()`（击打事件+上报+颜色）→ `light_tick()`（图案/白光自检）。
拨码 20ms 采样保留但与主机同构（**业务不得读 `SW_*`**，本板未接拨码）。
主机状态机段在从机构建里由 `#if BOARD_ROLE_MASTER` 关闭 → **从机只收不发**，不会与真主机抢 `0x161`。

```c
/* 1ms: */
motor_*                        → 删除（从机无电机）
hit_detect_task();             /* 击打判定(或放 4Hz) */
bsp_can1 排空 → 解码 → 状态   /* ⚠ 见第四节: 必须 1ms 级, 不能等 4Hz */
bsp_ws2812_refresh_all();
/* 4Hz: */
从机状态机抬升/灯效动画 + light_tick() + 上报
```

## 四、⚠️ 协议时序要求（从机必须满足，否则功能静默失效）

| 场景 | 主机发帧 | 间隔 | 要求 |
|---|---|---|---|
| 大符轮次切换 | 先 `0x01`(熄灭旧对) → 再 `0x02`(点亮新对) | **150ms** | **从机必须 1ms 级排空 CAN**，两帧都要看到；否则熄灭帧被后一帧覆盖 → 旧灯板不熄（老从机 200ms 单缓冲的固有缺陷，实测表现为"熄灭不稳定/一开始不熄灭"） |
| 打错复位 | `0x160` 上报 `[2]=0x01` | — | 主机侧"复位优先"判定，从机如实上报即可 |
| 规则上限 | "重新点亮前灯效熄灭至多 200ms" | — | 主机已取 150ms，从机不得引入额外延迟（如 200ms 阻塞） |

**结论**：从机把 `bsp_can1_pop()` 放 **1ms 节拍**里排空（只做"收帧→更新目标状态/置事件"），
灯效与状态机放 4Hz 逻辑帧。**禁止 `HAL_Delay(200)` 之类的阻塞**（老从机就是这么写的）。
