## 一、实施顺序与结论

```
P0 骨架 → P1 config → P2 灯带驱动 → P3 白光自检+灯效 → P6 大小符状态机 → P7 整机联调
                                          └─(并行)─ P4 CAN 双总线+协议 → P5 电机 ─┘
```

自底向上，每层完成即编译烧录验证；每阶段有可上板执行的硬验收；所有老代码数值的迁移以
《重构对照》第 9 节的 12 项核对表为验收依据。

| 阶段 | 结论 | 值得回查的决策与坑 |
|---|---|---|
| P0 骨架 | 完成 | `HAL_TIM_Base_Start_IT(&htim6)` 必须放在各模块 `*_init()` **之后**，否则节拍先跑、模块还没初始化；Keil 的 Include Paths 要加 `..\config;..\bsp;..\application` |
| P1 config 六件套 | 完成 | 拨码极性当时按旧注释假设填，P4 上板实测才定反（见下）；灯带表按实测把未接通道置 `led_num=0`，静态缓冲从约 42KB 降到约 4.4KB |
| P2 灯带驱动 | 完成 | 通道位算 `ch_idx = 1u << (channel >> 2)`；帧完成回调里**只清 busy、不调 `Stop_DMA`**（HAL 在 Normal 模式下进回调前已把通道复位为 READY）；每 tick 最多启动 2 条以保护中断耗时；GRB 高位先行 |
| P3 白光自检 + 灯效 | 完成 | 实测确定：中心灯带 = 索引 0 = TIM3_CH1 / PA6 / 88 颗，其余 5 个通道未接；**板面丝印与固件口径错位**（丝印 DIN2 标"中心圆环"实为 PB6 空置口）。结论已回填 `config_ws2812.h` 注释与《主机CubeMX配置清单》0.2 节。老 bug① 的"拨码即时变色"在此闭环 |
| P4 CAN + 协议 | 完成 | MASK 32 位过滤器：CAN1=bank0 收 `0x160~0x167`、CAN2=bank14 收 `0x200~0x207`，全部进 FIFO0（所以只开 RX0 中断）；发送"查一次空邮箱、满了就丢 + drop 计数"，零等待因此可在 TIM6 中断里调用；协议段 `pack/parse` 校验包头 `0xAA` + 命令范围 + 板号范围。拨码实测：**OFF/下=低、ON/上=高** → 三个 `*_ACTIVE_LEVEL=1`（高=转/蓝/大符） |
| P5 电机 | 代码完成 | 排空 CAN2 → 速度给定（小符 π/3、大符 `A·sin(wt)+B`）→ 目标积分 → 双环 P → 前馈 → 限幅 → 每 1ms 发 `0x200`（停转时也发 0 电流保活）。白光自检的触发从 SW2 改回编译期宏 `DEBUG_TEST_MODE`，SW2 归还"停/转"。**圈时间未标定**（M1） |
| P6 状态机 + 随机 | 完成 | 六个显式状态 + 1ms 计时（2.5s / 1s / 150ms）；从机上报解析**复位优先**（打错帧 `[1]` 会残留上一次的 `0x03`）；每 4Hz 只取一帧回报（与老代码单缓冲等效，不改变时序）；小符修正了老代码越界导致的"实际打 6 次"；大符"熄灭旧对→点亮新对"的间隔从老代码的约 1ms 改为 150ms（规则上限 200ms），这是新从机能收到熄灭帧的前提 |
| P7 整机联调 | 进行中 | 与**旧从机**对接已通过（协议逐字节兼容是硬约束）。已知限制（非缺陷）：与旧从机联调时大符"熄灭旧对"不稳定，归因于旧从机 200ms 单缓冲吞帧，新从机已修复 |
