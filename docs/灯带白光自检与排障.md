# 灯带白光自检与排障（主从通用）

> 做法只有一件事：把每条灯带**单独点亮 2 秒白色**，其余熄灭，循环遍历，用来把故障范围缩到"某一条"。
> 合并自原《白光测试指南》（主机，2026 已结项）与《从机灯带自检与排障》（2026-10 文档整理）。
>
> 两边的用途不同：主机当年**必须**扫描，因为旧固件的注释、板面丝印与实物不一致；从机**不需要**
> 标定，硬件与 2025 完全相同，老从机的灯数与映射就是规格，本文只是出问题时用的工具。

---

## 一、触发方式：只用编译期宏

改 `config/config_board.h` 的 `DEBUG_TEST_MODE` 为 `1`，重新编译烧录，上电即开始扫描；
验完改回 `0` 再烧一次（正式固件不带自检）。

```
DEBUG_TEST_MODE = 1 → 上电进入自检
    ├─ 建立"本机实接灯带"列表 = 所有 led_num > 0 的通道
    ├─ 每 2 秒（LIGHT_TEST_TICKS 8 × 250ms）换下一条：当前条整条白光，其余全灭
    └─ 无限循环；未接灯带的通道直接跳过，不会出现"等 2 秒黑场"
```

不要用开关触发：

- 主机：P5 之后 `SW2` 已归还"停/转"语义，测试触发不再挂开关（`TEST_TRIGGER_USE_SW2 = 0`）。
- 从机：板上**没有接拨码开关**，PD2/PB3/PB4 悬空 + 内部上拉 → 三个开关读数恒为高（恒"激活"）。
  若把 `TEST_TRIGGER_USE_SW2` 置 1，从机会**一上电就永久扫描**。从机的颜色与大小符一律取
  CAN 帧的 `[4]`/`[2]`，不得读本机开关。

## 二、通道对照表

### 主机（实测结论，2026）

| 索引 | 定时器通道 / 引脚 | 板面丝印 | 灯数 | 说明 |
|---|---|---|---|---|
| 0 | TIM3_CH1 / PA6 | DIN6（无中文标注） | **88** | **实测唯一实接的一条 = "中心"** |
| 1 | TIM3_CH2 / PA7 | DIN5 外灯臂 | 0 | 未接 |
| 2 | TIM3_CH4 / PB1 | DIN3 下灯带 | 0 | 未接 |
| 3 | TIM4_CH1 / PB6 | DIN2 中心圆环 | 0 | 丝印最可疑：标着"中心"实为空置口 |
| 4 | TIM4_CH2 / PB7 | DIN4 内灯臂 | 0 | 未接 |
| 5 | TIM4_CH3 / PB8 | DIN1 上灯带 | 0 | 未接 |

两条结论：板面丝印与固件口径**错位**，以实测为准；老主机固件里 4 路 DMA 是**从从机工程拷贝的
残留**（`main.c` 从未调用过任何图案函数），不代表物理上接了 4 条。未接的通道 `led_num` 置 0
后不分配缓冲、不发送，顺带释放约 38KB RAM。

### 从机（口径继承 2025，无需实测）

| 索引 | 定时器通道 / 引脚 | 老从机数组 | 灯数 | 功能 |
|---|---|---|---|---|
| 0 | TIM3_CH1 / PA6 | `LED_ROAD_3` | 87 | 上 |
| 1 | TIM3_CH2 / PA7 | `LED_ROAD_2` | 262 | **靶面**（环数与待激活图案） |
| 2 | TIM3_CH4 / PB1 | `LED_ROAD_4` | 320 | **灯臂**（箭头流动、进度条） |
| 3 | TIM4_CH1 / PB6 | `LED_ROAD_5` | 120 | **侧灯臂** |
| 4 | TIM4_CH2 / PB7 | `LED_ROAD_1` | 92 | 下 |
| 5 | TIM4_CH3 / PB8 | 老从机从不驱动 | 0 | `WS_LED_NUM_SPARE = 0`，不参与自检 |

映射依据是老从机的 DMA 绑定，已逐条核对与 `SLV_STRIP_*` 一致；环数段偏移、待激活段、箭头模板
都是 2025 逐颗数出的标定值，原样继承。

## 三、观察与记录

判读方法：调试器 Watch `g_dbg_ws_scan_idx`，读到的值就是"此刻亮着的那条"的索引（`0xFF` = 未在
扫描）。扫描期间当前条全程点亮，任何时候暂停都行，不受 2 秒节拍影响。

| 索引 | 通道 / 引脚 | 灯数（口径） | 实测亮 | 实测灯数 | 末端全亮 | 颜色纯白 | 备注 |
|---|---|---|---|---|---|---|---|
| 0 | TIM3_CH1 / PA6 | 主机 88 / 从机 87 | ☐ | |  | ☐ | |
| 1 | TIM3_CH2 / PA7 | 从机 262 | ☐ | |  | ☐ | |
| 2 | TIM3_CH4 / PB1 | 从机 320 | ☐ | | ☐ | ☐ | |
| 3 | TIM4_CH1 / PB6 | 从机 120 | ☐ | | ☐ | ☐ | |
| 4 | TIM4_CH2 / PB7 | 从机 92 | ☐ | | ☐ |  | |
| 5 | TIM4_CH3 / PB8 | 0（不驱动） | 需临时把 `WS_LED_NUM_SPARE` 改成非 0 才可试 | | | | 确认后改回 0，省约 4.4KB |

顺带可核对的项：红蓝切换是否即时生效（拨主机 SW3）、末端是否全亮（数个大概）。灯珠时序的量测
值（bit 1.25µs、T0H≈357ns、T1H≈893ns、复位段≈112µs）见《CubeMX校验与踩坑.md》第二节。

## 四、什么时候才需要改配置

- 从机：**只有与老口径不符才改**。灯数不符（末端不亮 = 实际颗数更多）改 `config_ws2812.h` 的
  `WS_LED_NUM_*`，灯带表与 DMA 缓冲都由它推导，只改这一处；功能索引不符改 `config_light.h` 的
  `SLV_STRIP_TARGET / ARM / ARM_SIDE / UP / DOWN`。没有不符就什么都不改，这正是继承口径的意义。
- 主机：换板、改线后重跑本流程，把"中心 = 哪个索引/通道"回填到 `config_ws2812.h` 注释与
  《主机CubeMX配置清单.md》0.2 节。
- 想让 PB8 参与自检：临时把 `WS_LED_NUM_SPARE` 改成非 0（如 90），它会出现在扫描序列里。

## 五、异常排查

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 上电没进自检 | 宏没置 1 或没重新烧录 | 确认 `DEBUG_TEST_MODE=1` 且已重编译烧录 |
| 轮到某条却全黑 | ①该口确实没接灯带（主机 1~5 全属这种，不是故障）②灯带插错端子 ③该通道 DMA/TIM 没配好 | 把已知好的灯带插到该端子试；仍黑 → 查该通道 DMA 方向是否为 `Memory To Peripheral`（《CubeMX校验与踩坑.md》第三节） |
| 完全没有 PWM 输出 | 该通道的 DMA/定时器配置 | 同上，并用逻辑分析仪勾对应引脚 |
| 末端一小段不亮 | 灯数填小了 | 点数后改大 `WS_LED_NUM_*` |
| 半条不亮 / 中间黑一段 | 虚焊、坏点、供电不足、线缆压降 | 就近单独给该条供电试；记入硬件问题清单 |
| 发红或发绿而不是纯白 | 位序或 RGB 顺序 | 新驱动是 MSB-first + GRB，老固件是 LSB-first（见《从机重构清单》SL12）；只有某一条异常而其他正常 → 查该条灯珠型号 |
| 轮转顺序与表格不符 | 灯带表顺序被改过 | 以 `g_dbg_ws_scan_idx` 为准记录，并更新本文表格 |
| 自检期间某条闪烁 | 该条 DMA 被重复启动 | Watch `dma_busy`，检查 `bsp_ws2812_refresh_all` 的 busy/dirty 与帧完成回调 |
| 退出自检后只有一条亮红/蓝 | 主机侧正常现象 | 主机灯效掩码只含索引 0；从机已换成图案库 |

## 六、验收

- [ ] `DEBUG_TEST_MODE=1` 的固件上电即自检，每 2 秒换一条，`g_dbg_ws_scan_idx` 随之变化
- [ ] 本机实接的灯带逐条能点亮，整条纯白无残点（异常按第五节定位并记录）
- [ ] 改回 `0` 后恢复正常灯色
- [ ] 从机：未发现与老口径不符 → 配置一处都不用改
