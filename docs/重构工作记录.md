# 重构工作记录 —— 2027 能量机关（大符/小符）固件

> 对象：`2025_Embedded-Buff/`（2025 赛季老固件，master + slave）→ `2027_Embedded_Buff/`（本次重构）
> 平台：STM32F405RGT6 + HAL，Keil MDK-ARM，CubeMX 6.15；主从共用同一块 PCB，分两个工程构建
> 本文三段：**为什么重构 → 重构后好在哪 → 结果展示**。逐条明细的出处都在 `docs/` 里（文末索引）。

---

## 一、为什么要重构（老代码有什么问题）

**结论先行**（与《重构对照》同一口径）：老代码的**驱动核心思想完全正确**——用
"PWM 周期 = 1 个 bit、DMA 逐 bit 灌 CCR"驱动 WS2812，这套东西原样继承、一个字没改思路。
问题全部集中在四类：**刷新调度缺失、层间耦合、协议裸字节、调度阻塞**，以及由此派生的
一批赛场/台架上真实暴露的缺陷。

### 1.1 结构性问题（不改就撑不住后续迭代）

| # | 问题 | 老代码里的表现 | 实际后果 |
|---|---|---|---|
| 1 | **一个 `main.c` 干所有事** | 老主机 `main.c` 809 行里同时有：CAN 收帧解析、大小符状态机、灯珠寄存器操作、EXTI 回调、电机 PID | 改任一模块要通读全文件；出问题时无法定位"是谁改了谁" |
| 2 | **配置散落、主从各说各话** | 灯数/引脚/超时/规则魔数写在 `main.c` 与 CubeMX 注释里；同一通道主从灯数都不一样（`PA6`：主机 88 / 从机 87；`PB1`：主机 256 / 从机 320） | 换板/改线要全文件搜数字；两版固件其实驱动的不是同一批物理灯带也看不出来 |
| 3 | **拷贝残留** | 主机工程是从从机工程拷来裁剪的：定义了 4 个灯带数组并启动 4 路 DMA，但主机板上**实测只接了 1 条**灯带，且 `main.c` 从未调用过任何图案函数 | 白占约 **38KB RAM**（128KB 的机器上）；数组注释与实物对不上，误导排查 |
| 4 | **隐式标志当状态机用** | `once` / `start` / `test_flag` / `counter` / `first_hit_flag` 互相耦合，状态含义靠上下文推断 | 竞态多、不可观测；"打错/超时/轮次切换"三条路径互相覆盖，改一处崩三处 |
| 5 | **阻塞式调度** | 主循环里 `HAL_Delay(200)`；CAN 发送 `while` 死等空邮箱；CAN 接收**单缓冲**（后帧覆盖前帧） | 一次阻塞 = 200ms 内所有事件积压；CAN2 掉线时死等邮箱直接卡死 |
| 6 | **协议裸字节** | `0x161`/`0x160` 帧字段用魔数下标散落读写；从机上报"打错"时只写 `[0]`、`[2]`，`[1]` 残留上一次的 `0x03`；无包头/命令/板号范围校验 | 总线上一帧坏数据能让主机推进错轮次；协议改动要在两个工程里逐处搜 |
| 7 | **随机数依赖 TIM2** | 老代码 `srand(CNT_my)` + TIM2 5Hz 中断喂 `random_seed` | 新架构删掉 TIM2 后 `CNT_my` 无人递增 → 随机流退化甚至每局重复 |
| 8 | **驱动位序反了** | 老 `WS2812.c` 按 **LSB-first** 移位（WS2812 要求 MSB-first） | 亮度定值 `10` 实际打到灯珠是 `80`；所有亮度值都是"歪打正着"，换正确驱动就暗 8 倍 |
| 9 | **数组越界读** | 老主机 `num[counter]` 在 `counter==5` 时越界读到相邻数组首元素 | 小符实际要击打 **6 次**（规则是 5 次），且行为依赖链接顺序 |
| 10 | **板号靠"按板编译"但无护栏** | 老从机 `#define BUFF_NUM 3`，改宏重编译，无越界检查、输出固件名不带板号 | 5 块板共用一个工程，烧错板号 = 打符流程错乱，且现场极难发现 |

### 1.2 赛场/台架真实暴露的功能缺陷

| 编号 | 现象 | 根因 |
|---|---|---|
| 老 bug① | **拨码切红蓝，灯不跟着变**（只在上电刷一次） | 灯色只在初始化路径写，业务循环里没有"变化即刷新" |
| 老 bug② | 跑着跑着**花屏/串色**（R 标颜色异常的病根） | 旧代码每圈**无条件重启 5 路 DMA**，撞上上一帧未完成的传输 |
| 老 bug③ | 灯带末端残点/整条偶发错乱 | 复位段裕量不足：老驱动 `WS2812_Reset_NUM=50` bit ≈62.5µs，只勉强过 50µs 规格 |
| 老 bug④ | 上电时序敏感：先改拨码再上电会出现中心灯带色序异常 | 拨码采样与灯带初始化顺序无约束（回归验证仍挂在待办 M2，未做） |
| 老从机固有缺陷 | 大符轮次切换时**旧灯板不熄灭** | 主机"熄灭旧对→点亮新对"老代码只隔 ≈1ms，而老从机是 200ms 主循环 + **CAN 单缓冲**（后帧覆盖前帧）→ 熄灭帧被吞 |
| 击打误判 | 碰一下电极可能报"打错"导致整局复位 | EXTI 配成双边沿 + 无消抖窗 + 表外引脚也参与判定 |
| 规则缺项 | **中部灯臂进度 n/5 从未实现**（规则 5.5.2.1 要求） | 双重根因：从机收到 `[6]=round` 但不渲染 + 老主机的 `[6]` 本来靠帧残留 |
| 无观测手段 | 出问题只能加打印 / 抱逻辑分析仪上台架 | 没有可 Watch 的状态快照，也没有丢帧计数 |

## 二、重构后好在哪里

### 2.1 架构上的变化（老 → 新）

| 维度 | 老代码 | 新代码 |
|---|---|---|
| **分层** | `main.c` + `Divice/WS2812.c` 两层混写 | `Core/`（CubeMX 生成，只动 USER CODE）→ `config/`（只放宏与 const 表）→ `bsp/`（硬件 + 中断收尾）→ `application/`（业务），**依赖只准向下**；文件按外设/模块命名，某个外设出问题 `config_<外设>.h → bsp_<外设>.c → application/<模块>.c` 三点一线查完 |
| **调度** | 主循环 + `HAL_Delay` + TIM2/TIM4 混用 | **TIM6 1ms 中断 = 唯一调度器**：1ms 排空 CAN + 状态机计时；20ms 采拨码（消抖 4 次 ≈80ms 生效）；250 分频的 4Hz 逻辑帧跑图案与上报消费；主循环空转。**全工程禁止阻塞式延时** |
| **灯带驱动** | 思路正确但一次性全刷、位序反 | 继承 PWM+DMA，加 **dirty/busy 握手**（只发变化过的条）、每 tick 最多启动 2 条（ISR 耗时保护）、**未接灯带的通道 `led_num=0` 不分配缓冲**（主机侧释放 ≈38KB）、位序改 **MSB-first** |
| **协议** | 裸字节散落 | `buff_frame_pack/parse` 单点 + 包头 `0xAA`/命令范围/板号范围校验；**主从两份 `buff.c` 的协议段逐字节一致**（可 diff 校验，改动必须两边同步） |
| **状态机** | `once/start/flag` 隐式标志 | 显式枚举：主机 `bb_state_t`、从机 `slv_state_t`、击打 `hd_st_t`；转换收敛到唯一入口（`go()` / `slv_enter()`） |
| **实时性（从机）** | 200ms 单缓冲收帧 | **1ms 排空 CAN + 逐帧锁存"与本板有关"的命令** → 1ms 换态、4Hz 消费击打事件；150ms 的"熄灯对"不再塌缩成"只见点亮" |
| **可观测性** | 加打印 | 一整套可 Watch 的快照结构体：`g_dbg_slv` / `g_dbg_hit` / `g_dbg_pat` / `g_dbg_buff_*` / `g_dbg_motor` / `g_buff_rx`，外加 **CAN 收发丢帧计数**、`age_ms`、`max_burst`、`imp_off`、`stale_hit` 等"硬证据"计数器 → 台架方法固定为**实机观察 + Watch，不依赖 CAN 分析仪** |
| **规则可调** | 写死在代码里 | 开关化：`BUFF_SMALL_HIT_COUNT`(5=规则/6=复刻老固件)、`BUFF_FIRST_HIT_TIMEOUT_EN`、`BUFF_EXTINGUISH_GAP_MS`(150，规则上限 200)、`SLV_IMPLICIT_OFF_EN`、`HD_IGNORE_MS`、`BUFF_BIG_REFRESH_EN/_MS`、`DEBUG_TEST_MODE` —— 赛前裁判有异议**改一行重编译** |
| **板号护栏** | 改宏无检查 | `SLAVE_PANEL_NUM` 越界直接 `#error` 编译不过 + 输出固件文件名带板号 + 烧录纪律写进指南 |
| **文档** | 一份手记（`大符思路.txt`） | `docs/` 14 份：路线图（主机 P0~P7 / 从机 S0~S8）、逐项清单、老新逐行对照、CubeMX 配置依据与操作说明、自检与排障指南、S7 台架五组验收指南（含故障树）、遗留待办总览（**完成即销项**） |

### 2.2 新解决的问题（含台架实测发现的真 bug）

| 问题 | 修法 | 判据/证据 |
|---|---|---|
| 老 bug①：拨码变色不即时 | `light_tick()` 每逻辑帧比对拨码并刷新（代码路径已改掉；台架记录表待回填） | 主机 P3 逐路白光 + 拨码切换 |
| 老 bug②：每圈无条件重启 DMA → 花屏 | **dirty/busy 握手**：只有内容变化的那条灯带才启 DMA，且每 tick 最多启动 2 条（ISR 耗时保护） | 连续运行 30min / 2h 无花屏（P3 与 M3 判据） |
| 老 bug③：复位段裕量不足 | 复位段由 50 bit(≈62.5µs) 加到 **90 bit ≈112µs**（差异表 #15，有意加强） | 逻辑分析仪：bit=1.25µs、T0H≈357ns、T1H≈893ns、复位段≈112µs |
| 老从机吞熄灭帧（旧灯板不熄） | 从机 1ms 排空 + 逐帧锁存（S3.1）；再加**点亮帧隐含熄灭**（差异 #21）做自愈；主机侧把间隔从 ≈1ms 改成 `BUFF_EXTINGUISH_GAP_MS=150`（规则上限 200） | `g_buff_rx.imp_off` 恒 0 = 一帧没丢；>0 = 曾丢帧且已自愈 |
| **3 块板同时亮**（大符，台架实测） | 差异 #21：大符点亮帧即"本轮该亮的集合"，不在集合里的板收敛到休眠 | 轮次切换后全场只应 2 块亮 |
| **大符打中的灯臂不熄灭**，看不出这块已打完 | 差异 #20：`light_set_big()` 按模式分叉，大符打中即保持熄灭（小符仍复刻老效果常亮） | `g_dbg_pat.big` |
| **被打过的板熄灭后一直不亮 / 主机老是整体复位** | 差异 #22：击打链路三个节拍（1ms EXTI / 4Hz 判定 / 4Hz 消费）跨 250ms 的竞态 → 转态即 `hit_detect_flush()` 作废在途击打，消费前再校验 `state==ARMED` | `g_dbg_slv.stale_hit`、`report_mishit` 只在真打错时涨 |
| 击打抖动误判打错 | EXTI 沿收敛为 FALLING（10 处 `.ioc` + 2 处 `gpio.c`）+ `HD_IGNORE_MS=100ms` 窗 + 表外引脚只计数不判定 | `g_dbg_hit.ignored` / `.stray` 恒 0 |
| 随机数每局可能重复 | 删 TIM2，上电用硬件 RNG 注入一次种子（`srand(bsp_rng_get_seed())`） | — |
| **大符随机到"同一对点两遍"** | M8：`buff_random_big()` 改为 C(5,2)=10 种组合里**无重复抽组**（部分 Fisher–Yates）。老算法实测相邻两轮同对 **10.0%**、一局平均 **0.91 次**重复 | 20 万局主机侧建模：同对 0 次、组合分布偏差 ±0.5% |
| **大符一直没被击打时不刷新** | M9：每 2.5s 无击打 → 熄灭旧对 → 150ms → 点亮**新一对**（不推进进度、不复位）；大符序列数据结构由"预生成 5 组"改为**组合领用池**（本局点过的每一对互不相同） | `g_dbg_buff_refresh` 递增而 `g_dbg_buff_round` 不变 |
| 小符击打次数越界（实际 6 次） | 默认按规则 5 次，`BUFF_SMALL_HIT_COUNT=6` 可显式复刻老行为（越界读改成有定义的行为） | — |
| CAN2 掉线死等邮箱 | 发送"查一次空邮箱满即丢" + `bsp_can1/2_tx_drop_count()`；接收双队列 + 溢出计数 | 断线时 drop 增长而系统不死机 |
| 空通道白占 RAM | 未接灯带的 5 个通道 `led_num=0`，不分配缓冲不发送 | map 文件核对，释放 ≈38KB |

### 2.3 新增的能力

- **灯带逐条白光自检**：`DEBUG_TEST_MODE=1` 编一份调试固件，上电即逐条点亮（只遍历本机实接的条），配合 `g_dbg_ws_scan_idx` 直接读"现在亮的是哪条通道"——主机靠它定位出"中心灯带 = 索引0 / TIM3_CH1 / PA6 / 88 颗"，并纠正了板上丝印与固件口径的错位。
- **大符周期刷新 + 组合不重复**（M9/M8，本轮新增）。
- **从机状态机与灯板图案库**（S4~S6）：待激活（19 段靶面 + 箭头流动）、已激活（环数段位查表 + 1 环六段特例）、全激活，标定表与老从机逐条核对继承。
- **`[6]=round` 进度链路已打通**：主机每帧带真实轮次、从机已镜像进 `g_dbg_slv.round` —— 但**中部灯臂 n/5 的渲染尚未实现**，作为 S8 专项排在 S7 台架全绿之后（规则要求项，老从机从未做过）。
- **S7 台架验收方法学**：五组串行（收帧链路 → 击打环数 → 状态机全流程 → 图案与亮度 → 5 板联机与烤机），每组给步骤/判据表/记录表/通过判据 + 一张"现象 → 先看哪个变量"故障树。

### 2.4 一句实话：代码变多了

| | 老主机 | 新主机 | 新从机 |
|---|---|---|---|
| 业务层代码行（`config`+`bsp`+`application`） | ≈1059（`main.c` 809 + `WS2812.c` 250） | 1905 | 2544 |

多出来的不是逻辑分支，而是**配置单点、协议校验、显式状态、诊断快照和"为什么这样写"的注释**。
交换比是：老代码出问题要通读全文件猜，新代码出问题先看一个 Watch 结构体就能定位到点。
