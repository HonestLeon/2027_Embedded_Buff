## 一、前提：主机板只接了 1 条灯带（实测接线）

### 1.1 结论与依据

| 项 | 结论 |
|---|---|
| 主机实接灯带 | **只有 1 条 —— “中心”那条** |
| 对应通道 / 引脚 | **TIM3_CH1 / PA6**（新代码 `strips[0]`，老固件 `LED_ROAD_3`） |
| 灯数 | **88**（老主机固件 `WS2812_LED_NUM_3`） |
| 依据 | ①老主机固件 `main.c` 旁维护者亲手注释：“中心的颜色刷新不正常（**对应 LED_ROAD_3**）”；②实测接线确认只有这一条 |

### 1.2 为什么老代码里看着有 4 条

老主机 `main.c` 定义了 4 个数组并启动了 4 路 DMA（`LED_ROAD_1~4`），但：

- 主机 `main.c` **从未调用过任何图案函数**（`Buff_*` 零命中）——只在上电刷一次颜色；
- 数组注释（扇心外部/外部扇叶/扇心内部/灯臂）与**从机工程一字不差**——主机工程是从从机拷贝裁剪的；
- 同一通道的灯数主从还不一致（`PA6`：主机 88 / 从机 87；`PB1`：主机 256 / 从机 320）——说明两版固件驱动的不是同一批物理灯带。

> 结论：那 4 路 DMA 是**拷贝残留**，不代表物理上接了 4 条。新代码已按实测把其余 5 个通道
> `led_num` 置 0（不分配缓冲、不发送），顺带省下约 **38KB RAM**。

### 1.3 本测试同时验证的事

| # | 验证项 | 说明 |
|---|---|---|
| 1 | 中心灯带能亮 | 通道/接线/驱动链路正确 |
| 2 | 显示纯白 | R/G/B 三通道都正确（发红/发绿 = 字节序或数据位错） |
| 3 | 整条全亮、无残点 | 老 bug“灯臂下半段不亮”同类硬件问题排查 |
| 4 | 灯数与 88 相符 | 核对 `config_ws2812.h` 的 `led_num` |
| 5 | 拨码极性与触发方式 | SW2 能否触发、红蓝切换是否即时生效 |

## 二、测试行为

```
SW2=ON(高电平) → 进入测试模式:
              遍历"本机实接灯带"(由 bsp_ws2812_led_num() > 0 判定)
              每 2 秒轮换一条(顺序=表索引 0→5), 其余熄灭, 无限循环

SW2=OFF(低电平) → 退出测试, 恢复红蓝常亮
```

**黑灯不等于故障**：未接灯带的通道直接跳过，不会出现“等 2 秒黑场”。

### 2.1 ★ 用变量读当前扫描到的通道(推荐, 不用掐秒表)

代码里有一个临时诊断变量（`application/light.c`）：

```c
volatile uint8_t g_dbg_ws_scan_idx;   /* 当前白光扫描到的灯带索引 0~5; 0xFF=未在扫描 */
```

**用法**：在 debugger 的 Watch 窗口加上 `g_dbg_ws_scan_idx`，测试模式下随时 **Halt**，
读到的值就是"此刻正在亮的那条灯带"的索引——**看中心灯带亮着的时候这个变量是几，
中心灯带就是那个通道**。（扫描期间当前条是全程点亮的，什么时候 Halt 都行，不受 2 秒节拍影响。）

索引 ↔ 通道/引脚/丝印 对照：

| 索引 | 定时器通道 | 引脚 | 板上丝印 |
|---|---|---|---|
| 0 | TIM3_CH1 | PA6 | DIN6（无标注） |
| 1 | TIM3_CH2 | PA7 | DIN5 外灯臂 |
| 2 | TIM3_CH4 | PB1 | DIN3 下灯带 |
| **3** | TIM4_CH1 | PB6 | **DIN2 中心圆环 ← 丝印最可疑** |
| 4 | TIM4_CH2 | PB7 | DIN4 内灯臂 |
| 5 | TIM4_CH3 | PB8 | DIN1 上灯带 |

> 看不到变量的情况：①变量名拼错；②优化等级太高把变量优化掉了（用 -O0/-O1）；
> ③没重新编译烧录。

## 三、操作步骤

1. 编译烧录当前固件（0 Error 0 Warning）；
2. 机构灯带按丝印插回 DIN 端子，接好 24V；
3. **SW2（停/转）拨到 ON**；
   - 电机代码尚未落地（P5），SW2 暂时兼作测试触发；
   - **若拨了没反应**（灯带仍是红/蓝）：大概率 `SW_RUN_ACTIVE_LEVEL` 极性假设反了，
     把 SW2 拨到另一侧再试。**这个现象要记录**（P4.5 极性核对项）；
4. 观察中心灯带：应**整体纯白**；
5. **SW2 拨回 OFF** → 恢复正常红蓝；此时拨 **SW3** 切换红/蓝，观察灯色是否**立即变化**
   （老 bug① 验收点）；
6. 用手机拍照/录像留档，便于对比。

## 五、中心灯带不亮时的排查顺序

1. **确认接线**：这条灯带的数据线是否插在丝印 `DIN?` 对应的端子上——**注意丝印与固件口径错位**：
   老固件的“中心”在 `PA6`（新代码索引 0），但板上丝印把 `PA6` 标成了 `DIN6`（无中文标注）；
2. **换索引试**：把 `config_ws2812.h` 的 `88u` 依此挪到索引 1/2/4（`PA7`/`PB1`/`PB7`）重新烧录，
   看是否点亮（每次只改一处，改完记下哪个通道对应“中心”）；
3. **量波形**：逻辑分析仪勾对应引脚，若完全没有 PWM 输出 → 检查该通道 DMA/TIM 配置；
   若有波形但灯不亮 → 灯带方向（DIN/DOUT 接反）或供电问题；
4. 确认后**回填**：把“中心 = 哪个索引/通道”写回 `config_ws2812.h` 注释与
   《主机CubeMX配置清单.md》0.2 节的对照表。
