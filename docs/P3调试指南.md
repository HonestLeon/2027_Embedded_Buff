# P3 灯带不亮 —— 已定位: DMA 方向配反(附排查指南)

> ## ✅ 根因(已定位)
>
> **6 条 WS2812 DMA 流的 `Direction` 配成了 `Peripheral To Memory`，应为 `Memory To Peripheral`。**
> （老工程能工作的生成代码是 `hdma_xxx.Init.Direction = DMA_MEMORY_TO_PERIPH`；
> 新工程生成的是 `DMA_PERIPH_TO_MEMORY`。）
>
> **机理**（`HAL_DMA_Start_IT` 按 Direction 映射地址，已核对本工程 hal_dma.c L1158~1176）：
> - 正确 `MEMORY_TO_PERIPH`：`PAR = &CCR1`（固定，PINC=0）、`M0AR = ccr_buf`（递增，MINC=1）
>   → 缓冲区逐个灌进 CCR1 ✅
> - 错误 `PERIPH_TO_MEMORY`：`PAR = ccr_buf`（**PINC=0 → 永远只读 buffer[0]**）、
>   `M0AR = &CCR1`（**MINC=1 → 写地址每 +2 递增，冲出 TIM3 寄存器块**）❌
>
> **后果**：
> 1. `CCR1` 拿不到正确的占空比序列 → 输出恒低 → **灯带全黑**；
> 2. 写地址从 CCR1 一路递增：CCR1→CCR2→CCR3→CCR4→BDTR→DCR→DMAR→OR，
>    然后扫过 `TIM4`、`TIM5`、**`TIM6`（1ms 调度定时器）**、`TIM7` 的寄存器
>    → 调度被破坏（这也解释了为何连白光测试模式都毫无反应）；
> 3. **铁证**：读到的 `TIM3->DMAR = 0x00000001` —— 我们的代码从不写这个寄存器，
>    是被这个失控的 DMA 写进去的。
>
> **修复**：CubeMX → System Core → DMA → 6 条流 `Direction` 全部改为
> **Memory To Peripheral** → 重新生成代码 → **断电重启**（失控 DMA 破坏过外设寄存器，
> 必须复位）→ 烧录 → 验证。其余三项不用改（PeriphInc 不勾 / MemInc 勾 / 双方 Half Word）。
>
> **教训**：`.ioc` 里的 `Direction` 字段历史值与生成代码可能不一致，
> **判据要以能工作的老工程生成代码为准**。

## 以下为原始排查指南（保留备查）

> 适用现象：新固件烧录后中心灯带**完全不亮**（旧固件能亮）。
> 已排除的项：CubeMX 静态配置全部核对无误（GPIO AF、DMA 挂接、PWM 模式、引脚冲突、
> 初始化顺序、TIM6 中断使能）。所以问题在**动态链路**：调度 → 驱动 → DMA → 硬件。
>
> 已加入两个**临时诊断点**（定位后删除）：
> - `main.c` USER CODE 2：`light_init()` 后直接调一次 `bsp_ws2812_refresh_all()`
>   → 区分「驱动问题」和「中断调度问题」
> - `it.c`：全局变量 `g_dbg_isr_cnt`，TIM6 中断每 1ms +1
>   → 直接看中断有没有跑

---

## 0. 准备

1. Keil 切到 **Debug 配置**，确认优化等级是 **-O0 或 -O1**（-O3 下局部/静态变量常被优化掉，
   Watch 窗口看不到，且断点会乱跳）；
2. 重新编译烧录（含上面两个诊断点），**Ctrl+F5 进入调试**；
3. 打开 **Watch 1** 窗口（View → Watch Windows → Watch 1）。

---

## 1. 第一次判定：全速运行 3 秒后按 Halt

看黄色箭头停在哪里：

| 停在哪 | 结论 | 下一步 |
|---|---|---|
| `main` 的 `__WFI()` 附近 | 主循环正常空转 | → 第 2 步 |
| `HardFault_Handler` | **硬件异常**：驱动里有空指针/越界 | → 第 5 步（故障定位） |
| `HAL_Delay` / `bsp_rng_get_seed` 里 | 初始化卡住（RNG 未就绪？） | → 单步跳出来看 |
| 其它中断里反复 | 有中断失控 | → 看 Call Stack |

---

## 2. 第二步：看中断是否在跑（最重要的分岔点）

在 **Watch 1** 里输入并观察：

```
g_dbg_isr_cnt
```

| 观察结果 | 结论 | 下一步 |
|---|---|---|
| **数值在涨**（每 1ms +1，1 秒涨约 1000） | TIM6 中断正常 → 问题在**驱动/DMA/硬件** | → 第 3 步 |
| **一直是 0** | TIM6 中断没跑 → 调度链路没通 | → 第 4 步 |

> 注意：全速跑时 Watch 不一定实时刷新，**按 Halt 后再看数值，再按 Run，再 Halt** 对比两次。

---

## 3. 如果中断正常：查驱动与 DMA 链路

### 3.1 在 `bsp_ws2812_refresh_all()` 打断点

`bsp_ws2812.c` 里找到 `void bsp_ws2812_refresh_all(void)`，在**函数第一行**设断点，Run。

- **断点命中** → 在 Watch 里看（或 F10 单步过一遍）：

  | 表达式 | 期望值 | 含义 |
  |---|---|---|
  | `s_strips[0].led_num` | `88` | 灯带表读到了 |
  | `s_strips[0].dirty` | `1` | light_init 确实置了待发标志 |
  | `s_strips[0].dma_busy` | `0` | 没在忙 |
  | `s_strips[0].ccr_buf` | 非 `0x00000000` | 缓冲已挂接 |
  | `s_strips[0].rgb` | 非 `0x00000000` | 缓冲已挂接 |
  | `*(uint16_t*)s_strips[0].ccr_buf` | `25` 或 `10` | 翻译后的 CCR 值（T1H/T0H） |

　　（若 Watch 里看不到 `s_strips`：它定义在 `bsp_ws2812.c` 里，
　　把调试上下文切到该文件，或改用 `bsp_ws2812_led_num(0)` 之类的调用观察。）

- **断点不命中**（且 `g_dbg_isr_cnt` 在涨）→ 说明中断跑的是别的分支 / 编译没更新 →
  重新 Rebuild，确认 `bsp_ws2812.c` 在 Keil 的 `bsp` Group 里。

### 3.2 单步过 `HAL_TIM_PWM_Start_DMA` 调用，看返回值

F10 单步到下一行，然后看：

| 表达式 | 期望值 | 若不符 |
|---|---|---|
| `htim3->State` | `HAL_TIM_STATE_BUSY(0x24)` 或 READY | — |
| `TIM3->CR1` | 末位 `CEN=1`（0x0001 或 0x0081） | CEN=0 → 计数器没启动 |
| `TIM3->CCER` | bit0 `CC1E=1` | =0 → 通道输出未使能 |
| `TIM3->CCR1` | `10`~`25` 之间变化 | 恒 0 → DMA 没在灌 |
| `TIM3->CNT` | 在 0~34 之间跳动 | 不动 → 计数器没跑 |
| `DMA1_Stream4->CR` | bit0 `EN=1`（运行中） | EN=0 → DMA 没启动 |
| `DMA1_Stream4->NDTR` | 从 2202 递减到 0 | 不减 → 传输没进行 |
| `DMA1_Stream4->PAR` | `&TIM3->CCR1`（0x40000434） | 不符 → DMA 目标地址错 |
| `DMA1_Stream4->M0AR` | `s_ccr0` 的地址 | 不符 → 源地址错 |
| `GPIOA->MODER` | PA6 那两位 = `10`（复用） | =00/01 → **引脚没配成复用** |
| `GPIOA->AFR[0]` | PA6 的 4 bit = `2`（AF2） | 不符 → 复用功能错 |

### 3.3 在 `HAL_TIM_PWM_PulseFinishedCallback` 打断点

- **命中** → 一帧发完了 → 软件链路完全正常 → 问题在**硬件侧**（灯带接线/方向/供电，或引脚）；
  → 用逻辑分析仪量 PA6 波形确认；
- **不命中** → DMA 没传完（配合 3.2 的 NDTR 判断卡在哪）。

---

## 4. 如果 `g_dbg_isr_cnt` 不涨：查 TIM6 与 NVIC

Watch 里加这些寄存器：

| 表达式 | 期望值 | 含义 |
|---|---|---|
| `TIM6->CR1` | bit0 `CEN=1`、bit7 `ARPE=1` | 计数器使能 |
| `TIM6->DIER` | bit0 `UIE=1` | 更新中断使能 |
| `NVIC->ISER[1]` | bit22 = 1 | TIM6_DAC_IRQn（中断号 54）在 NVIC 使能 |
| `NVIC->IP[54]` | 抢占优先级 2（0x20） | 优先级 |
| `TIM6->PSC` / `TIM6->ARR` | 83 / 999 | 1kHz |

判定：

- `CEN=0` → `HAL_TIM_Base_Start_IT(&htim6)` 没执行到 → 检查 `main.c` USER CODE 2
  （是不是被 `HAL_Delay(100)` 之前的某个初始化卡住了？单步确认执行到了这一行）；
- `CEN=1` 但 `ISER` bit=0 → NVIC 没使能 → 回 CubeMX 勾选 TIM6_DAC_IRQn 重新生成；
- 都正常但 `g_dbg_isr_cnt` 不涨 → 检查 `stm32f4xx_it.c` 里 `TIM6_DAC_IRQHandler`
  是否调用了 `HAL_TIM_IRQHandler(&htim6)`；以及 `HAL_TIM_PeriodElapsedCallback`
  里 `if (htim == &htim6)` 判断是否成立。

---

## 5. 如果是 HardFault

1. Halt 后在 Watch 看：
   ```
   SCB->HFSR      // 0x40000000 = FORCED(由别处升级而来)
   SCB->CFSR      // 细分: IMPRECISERR / PRECISERR / IBUSERR / UNDEFINSTR ...
   ```
2. 看 **Call Stack** 窗口（View → Call Stack Window），往上找**你的函数名**——通常就是出错的那一层；
3. 常见嫌疑（按概率）：
   - `translate()` 往 `ccr_buf` 写越界（缓冲长度与 `led_num` 不一致）；
   - `set_rgb` 的 start+count 越界（已有防护，但配置不同步时仍可能）；
   - 缓冲指针为 NULL 却 `memset`（`bsp_ws2812_init` 里已有 `continue` 防护）；
   - DMA 目标地址错（看 `DMA1_Stream4->PAR`）。

---

## 6. 判定表速查

| 现象 | 结论 | 对策 |
|---|---|---|
| `g_dbg_isr_cnt` 不涨 | 调度没跑 | 查 TIM6 CR1/DIER/NVIC（第 4 步） |
| 中断涨，`refresh_all` 断点命中但灯不亮 | 驱动发出去了，硬件侧问题 | 量 PA6 波形；查灯带 DIN/DOUT 方向、供电、接触 |
| 中断涨，`refresh_all` 里 `dirty=0` | `light_init` 没置上（顺序/掩码问题） | 检查 `LIGHT_LOCAL_STRIP_MASK` 与 `light_init` 调用顺序 |
| `TIM3->CCR1` 恒 0、`CNT` 在动 | DMA 没灌数据 | 查 `DMA1_Stream4->CR`、`HAL_DMA_Init` 是否执行 |
| `GPIOA->MODER` PA6 不是复用 | 引脚被别的初始化覆盖 | 查 `gpio.c` 是否误配 PA6、`HAL_TIM_MspPostInit` 是否执行 |
| HardFault | 软件越界/空指针 | 看 CFSR + Call Stack（第 5 步） |

---

## 7. 定位完的清理动作

1. 删除 `main.c` 里那行临时 `bsp_ws2812_refresh_all();`
2. 删除 `it.c` 里的 `g_dbg_isr_cnt`（或保留：它只有 4 字节，留着做运行状态指示也行，
   但要在注释里说明用途）；
3. 按实测结果收敛 `config_ws2812.h` 灯带表（只留实接通道 + 真实灯数）
   与 `bsp_ws2812.c` 的缓冲指针表。
