# 从机通道扫描指南（S2 验收）

> 目的：把从机板 6 个 WS2812 通道与本机实接灯带的关系**用实验定下来** ——
> ①每条灯带的**灯数**；②**索引 ↔ 物理位置/功能**（哪条是靶面、哪条是灯臂、哪条是进度条）；
> ③**PB8（TIM4_CH3）到底接没接灯带**；④灯带**颜色是否纯白**（位序正确性）。
>
> 依据：《从机代码重构计划》S2、《从机重构清单》§二；方法沿用主机《白光测试指南》的经验。
> 前置：S1 已完成（`BOARD_ROLE_MASTER=0`、灯带表与缓冲已建好）；从机板接线/24V 已就绪。

---

## 一、为什么必须先做这一步

1. **老口径没在 2027 板上验证过**：`config_ws2812.h` 里的灯数（87/262/320/120/92）是**2025 老从机**
   的值，2027 板是否一致未知；
2. **丝印不可信**：主机板就吃过亏 —— 丝印把"中心圆环"标在 PB6 上，而实物中心灯带其实在 PA6
   （详见《主机CubeMX配置清单》0.2 节）。从机同样**只信实测**；
3. **S6 图案要靠它**：`config_light.h` 里的 `SLV_STRIP_TARGET / SLV_STRIP_ARM / SLV_STRIP_ARM_SIDE`
   决定"环数画在哪条、箭头流动画在哪条、进度条画在哪条"，这些索引**必须由本次扫描确认**；
4. **顺带验证驱动**：白光 = R/G/B 三通道同时满亮 → 一次验完"时序正确/三色正确/整条无坏点"。

## 二、扫描原理与行为

```
SW2 拨 ON(高电平)  → 进入扫描模式(约 80~100ms 后生效: 20ms 采样 + 4 次消抖)
      ├─ 建立"本机实接灯带"列表 = 所有 led_num > 0 的通道
      ├─ 每 2 秒（= LIGHT_TEST_TICKS 8 × 250ms）轮换到下一条
      │    当前条：整条白光；其余条：全灭
      └─ 无限循环，直到 SW2 拨 OFF

SW2 拨 OFF        → 退出扫描，恢复正常灯色(红/蓝, 随 SW3)
```

**从机可以用 SW2 直接触发**，因为从机没有电机（主机侧 SW2 是"停/转"，所以主机只能靠
`DEBUG_TEST_MODE` 宏触发）。触发方式由 `config/config_board.h` 决定：

| 宏 | 值 | 效果 |
|---|---|---|
| `TEST_TRIGGER_USE_SW2` | **1**（从机当前设置） | SW2 拨 ON 进扫描（**推荐，现场随手可扫**） |
| `DEBUG_TEST_MODE` | 0 | 备用：置 1 → 上电即进扫描（调试固件专用） |

**扫描顺序 = 灯带表行号顺序**（`config_ws2812.h` 的 `WS2812_STRIP_TBL`）：

| 轮次 | 索引 `g_dbg_ws_scan_idx` | 定时器通道 / 引脚 | 老从机口径 |
|---|---|---|---|
| 1 | **0** | TIM3_CH1 / PA6 | `LED_ROAD_3` "上"，87 |
| 2 | **1** | TIM3_CH2 / PA7 | `LED_ROAD_2` "中"(靶面)，262 |
| 3 | **2** | TIM3_CH4 / PB1 | `LED_ROAD_4` "灯臂"，320 |
| 4 | **3** | TIM4_CH1 / PB6 | `LED_ROAD_5` "侧灯臂"，120 |
| 5 | **4** | TIM4_CH2 / PB7 | `LED_ROAD_1` "下"，92 |
| 6 | **5** | TIM4_CH3 / PB8 | 老从机**从未驱动**，现填 90 试探值 |

> 一轮 16 秒（6 条 × 2s + 切换开销）。**PB8 填 90 是刻意的试探值**：扫描只遍历
> `led_num > 0` 的通道，填 0 就永远扫不到它、也就无法判断该口有没有接灯带。
> 多发的部分是"没接的灯珠"，无害。

## 三、操作步骤

1. **接线检查**：5~6 条灯带按**板端端子**插好（不用管丝印上的名字）；24V 供电正常；
2. 编译烧录从机固件（`TEST_TRIGGER_USE_SW2=1`，`DEBUG_TEST_MODE=0`）；
3. **SW2 拨 ON** → 应进入扫描；
   - 若没反应：先确认**开关极性**（实测结论：ON/上 = 高电平）；拨到另一侧再试；仍无反应见第六节；
4. **观察**（建议手机录一整轮 16 秒，事后逐帧回看）：
   - 记下"**当下亮的是哪一条、在机构的什么位置**"，同时用调试器读 `g_dbg_ws_scan_idx`；
   - 逐条看：**是否整条全亮到末端**（末端不亮 = 灯数填小了）、**颜色是否纯白**（发红/发绿 = 位序问题）、
     有无半条不亮/坏点；
5. **至少看两轮**确认轮转顺序稳定；
6. 记完 **SW2 拨 OFF** → 应恢复正常灯色（此时只有 `LIGHT_LOCAL_STRIP_MASK` 里的灯带按红/蓝常亮，
   见第六节第 6 条）；
7. 退出后按第五节回填配置。

**填表要求**

- "物理位置/功能"用**自己认得的参照系**（"贴着靶面那一圈""转臂外侧那条""中间竖着的那根"…），
  别用上/中/下 —— 那些词正是有争议的；功能一栏的目标是回答：**靶面是哪条？灯臂是哪几条？进度条是哪条？**

- 异常一律记下来（半条不亮、坏点、颜色偏色、闪烁）。

## 五、结果回填（三处）

### 5.1 `config/config_ws2812.h` —— 灯数（唯一来源）

只需改这一处命名宏，**灯带表与 `bsp_ws2812.c` 的 DMA 缓冲会自动跟随**（同一源，不会越界）：

```c
#define WS_LED_NUM_UP            87u   /* 索引0 —— 改成实测值 */
#define WS_LED_NUM_TARGET       262u   /* 索引1 */
#define WS_LED_NUM_ARM          320u   /* 索引2 */
#define WS_LED_NUM_ARM_SIDE     120u   /* 索引3 */
#define WS_LED_NUM_DOWN          92u   /* 索引4 */
#define WS_LED_NUM_SPARE         90u   /* 索引5: 实测不亮 → 改 0(不分配/不发送); 亮 → 改成实测灯数 */
```

> RAM 提醒：6 条全在时约 **49.6KB**（实测 `.bss`），主 SRAM 112KB 充裕；若 PB8 确认不接灯带，
> 把它改成 0 可再省 ~4.4KB。

### 5.2 `config/config_light.h` —— 功能索引映射

```c
#define SLV_STRIP_TARGET      1u   /* 靶面(环数 + 待激活图案) —— 按实测改 */
#define SLV_STRIP_ARM         2u   /* 灯臂(箭头流动 + 进度条) */
#define SLV_STRIP_ARM_SIDE    3u   /* 侧灯臂(进度条) */
#define SLV_STRIP_UP          0u   /* 上 */
#define SLV_STRIP_DOWN        4u   /* 下 */
```

> ⚠️ 若实测发现**灯臂/侧灯臂其实是两条独立的灯臂**（2027 机械可能改过），
> 就在这里把 `SLV_STRIP_ARM` / `SLV_STRIP_ARM_SIDE` 指到正确索引，
> 并在本表备注哪条对应"内灯臂/外灯臂"。

### 5.3 文档回填

- 把**填好的第四节表格**贴回 `docs/从机重构清单.md` §二（替换"待实测"字样）；
- 若发现与老口径不一致（灯数/功能对应），在《重构对照》§6.3（环数标定）或对应段落加一句实测结论；
- 机械布局若仍不确定（如"哪条是靶面"要看机构安装），标注为 **H5 待确认** 并写进《遗留待办与开放问题》。

## 六、异常排查

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 拨 SW2 无反应 | 开关极性判断错 | 拨到另一侧；仍不行改 `DEBUG_TEST_MODE=1` 重编（上电即扫） |
| **某条全黑，但轮到了它** | ①该口没接灯带（正常，PB8 就是这种）；②灯带插错端子；③该通道 DMA/TIM 没配好 | 换个已知好的灯带插到该端子试；若仍黑 → 查该通道的 DMA 方向是否 `Memory To Peripheral`（《CubeMX裁剪说明》§5） |
| **末端一小段不亮** | 灯数填小了 | 点数后改大 `WS_LED_NUM_*` |
| **末段过后还有一段不亮** | 多发了（无害）或灯带本身有坏点 | 确认实际颗数；坏点记入硬件问题清单 |
| **半条不亮 / 中间黑一段** | 硬件：供电不足、虚焊、线缆过长压降 | 单独给该条灯带就近供电试；记入硬件问题 |
| **发红/发绿而不是纯白** | 位序或 RGB 顺序错 | 新驱动是 MSB-first + GRB（老固件是 LSB-first —— 见《从机重构清单》SL12）；需复查 `bsp_ws2812.c` 的 `ws2812_translate`；若**单条**异常而其他正常，查该条灯带的灯珠型号 |
| **轮转顺序与表格不符** | 灯带表顺序被改过 / 实接顺序不同 | 以 `g_dbg_ws_scan_idx` 为准记录，并同步更新第二节表格 |
| **退出扫描后只有一条亮红/蓝** | 正常现象 | `light.c` 还是**主机版**的灯效（`LIGHT_LOCAL_STRIP_MASK` 只含索引0），S6 会整体替换为从机灯板图案 |
| **扫描期间有条带闪烁** | 该条 DMA 每 tick 被重复启动（极少见） | 查 `bsp_ws2812_refresh_all` 的 busy/dirty 与帧完成回调是否正常（Watch `dma_busy`） |

## 七、验收标准（S2 DoD）

- [ ] SW2 拨 ON 能在 ~100ms 内进入扫描；OFF 能退出
- [ ] 6 条（或 5 条）通道**逐条**点亮，位置可辨认、可重复（看两轮结果一致）
- [ ] 每条灯带**末端全亮**、颜色**纯白**
- [ ] **PB8（索引5）有结论**：接/未接 + 灯数
- [ ] `WS_LED_NUM_*` 全部回填为实测值（PB8 不接则置 0）
- [ ] `SLV_STRIP_TARGET / ARM / ARM_SIDE / UP / DOWN` 五处索引确认到位
- [ ] 第四节表格填完并贴回《从机重构清单》§二
- [ ] 编译 0 Error 0 Warning，回填后仍能正常扫描
