# 从机灯带自检与排障（可选工具）

> **定位：这不是标定步骤，也不是必经阶段。**
> **硬件与 2025 完全相同** ⇒ 老从机的灯数（87/262/320/120/92）与"索引 ↔ 功能"映射**就是规格**，
> 已直接继承进 `config_ws2812.h` / `config_light.h`，**无需实测标定**（2026-10 确认）。
>
> 本文只在**出问题时**用：某条灯带不亮、某段显示位置不对、换了灯带/改了接线、或想确认某条的颗数。
> 逐条点亮 = "把每条灯带单独点亮 2 秒"，用来把故障范围缩到"某一条"。

---

## 一、为什么不标定（结论先行）

| 项 | 依据 | 是否需要实测 |
|---|---|---|
| 灯带颗数 | 硬件与 2025 相同 ⇒ 老 `WS2812.h` 的 87/262/320/120/92 有效 | ❌ 不需要 |
| 索引 ↔ 功能映射 | 老从机的 DMA 绑定即映射：`LED_ROAD_3→TIM3_CH1`、`ROAD_2→TIM3_CH2`、`ROAD_4→TIM3_CH4`、`ROAD_5→TIM4_CH1`、`ROAD_1→TIM4_CH2` | ❌ 不需要（已核对 `SLV_STRIP_*` 逐条一致）|
| 环数段偏移 / 待激活段 / 箭头模板 | 2025 逐颗数出的标定值，原样继承 | ❌ 不需要（只许搬位置）|
| PB8（TIM4_CH3） | 老从机**从不驱动**该口 | ❌ 按老行为 `WS_LED_NUM_SPARE = 0` |

> 主机板当时之所以必须扫描，是因为**旧主机固件的注释/丝印与实物不一致**且只接了 1 条灯带；
> 从机没有这个问题（硬件未变、老固件就是规格）。

---

## 二、什么时候才用它

- S5/S6 联调时发现**某一条灯带完全不亮**（先确认是不是这条的问题，还是这一路驱动/接线的问题）；
- 某段图案的**位置不对**（例如环数显示偏了 → 怀疑该条灯带的实际颗数与老口径不符）；
- 换了灯带、或改动过接线（端子重插、灯带剪短/拼接）；
- 想确认某条灯带的**实际颗数**（末端是否全亮）。

---

## 三、怎么用（**只能用编译期宏触发**）

⚠️ **从机板没有接拨码开关**（PD2/PB3/PB4 悬空 + 内部上拉 → 三个 `SW_*` 恒为高电平）。
所以：
- **不能用 SW 触发**（`TEST_TRIGGER_USE_SW2` 已置 0 —— 若置 1，因读数恒为"高=激活"，从机会
  **一上电就永久进入扫描模式**）；
- 只能用 **`DEBUG_TEST_MODE` 宏**：改 `config/config_board.h` → 置 `1` → 重新编译烧录 → 上电即扫；
- 用完**记得改回 0**（正式固件不带自检）。

```
DEBUG_TEST_MODE = 1 编译烧录 → 上电即进入自检
    ├─ 建立"本机实接灯带"列表 = 所有 led_num > 0 的通道（当前 5 条；PB8 已置 0 不参与）
    ├─ 每 2 秒（= LIGHT_TEST_TICKS 8 × 250ms）轮换到下一条
    │    当前条：整条白光；其余条：全灭
    └─ 无限循环

改回 DEBUG_TEST_MODE = 0 → 恢复正常灯色（此时只有掩码内的灯带按红/蓝常亮，S6 会替换该逻辑）
```

**扫描顺序 = 灯带表行号顺序**（`WS2812_STRIP_TBL`）：

| 轮次 | `g_dbg_ws_scan_idx` | 定时器通道 / 引脚 | 老从机口径（= 规格） | 功能 |
|---|---|---|---|---|
| 1 | **0** | TIM3_CH1 / PA6 | `LED_ROAD_3`，87 | 上 |
| 2 | **1** | TIM3_CH2 / PA7 | `LED_ROAD_2`，262 | **靶面**（环数 + 待激活图案）|
| 3 | **2** | TIM3_CH4 / PB1 | `LED_ROAD_4`，320 | **灯臂**（箭头流动 + 进度条）|
| 4 | **3** | TIM4_CH1 / PB6 | `LED_ROAD_5`，120 | **侧灯臂**（进度条）|
| 5 | **4** | TIM4_CH2 / PB7 | `LED_ROAD_1`，92 | 下 |
| — | 5 | TIM4_CH3 / PB8 | 老从机从不驱动 | `WS_LED_NUM_SPARE = 0`，不参与自检 |

> 想让 PB8 也参与自检（例如怀疑该口其实接了灯带）：把 `WS_LED_NUM_SPARE` **临时**改成非 0
> （如 90），它就会出现在扫描序列里；确认后改回 0（省 ~4.4KB RAM）。

**操作**：烧录带 `DEBUG_TEST_MODE=1` 的固件 → 上电 → 观察（建议录像一整轮）→ 同时读
`g_dbg_ws_scan_idx` 确认"当前亮的是哪条"→ 完事改回 0 重烧。

## 五、只有当"与老口径不符"时才回填

- **灯数不符**（末端不亮 → 实际颗数更多；多发了 → 更少）：改 `config/config_ws2812.h` 的
  `WS_LED_NUM_*` —— **灯带表与 DMA 缓冲都由它推导，只改这一处**；
- **功能索引不符**（例如靶面其实不在这条）：改 `config/config_light.h` 的
  `SLV_STRIP_TARGET / ARM / ARM_SIDE / UP / DOWN`，并在本文档与《从机重构清单》§二 备注实测结论；
- **PB8 确认接了灯带**：`WS_LED_NUM_SPARE` 改成实测灯数（表与缓冲自动跟随）。

> 没有发现不符，就**什么都不用改** —— 这正是"口径继承"的意义。

## 六、异常排查

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 上电没有进入自检 | `DEBUG_TEST_MODE` 没置 1 / 没重新烧录 | 确认宏为 1 且已重编译烧录 |
| **某条全黑，但轮到了它** | ①该口确实没接灯带；②灯带插错端子；③该通道 DMA/TIM 没配好 | 把已知好的灯带插到该端子试；仍黑 → 查该通道 DMA 方向是否 `Memory To Peripheral`（《CubeMX裁剪说明》§5）|
| **末端一小段不亮** | 灯数填小了（实际颗数更多）| 点数后改大 `WS_LED_NUM_*` |
| **整条全黑但驱动器正常** | 供电不足 / 虚焊 / 线缆过长压降 | 就近单独给该条供电试；记入硬件问题清单 |
| **半条不亮 / 中间黑一段** | 硬件（虚焊、坏点、供电）| 同上；记入硬件问题清单 |
| **发红/发绿而不是纯白** | 位序或 RGB 顺序问题 | 新驱动是 **MSB-first + GRB**（老固件是 LSB-first，见《从机重构清单》SL12）；若只有某一条异常而其他正常 → 查该条灯珠型号 |
| **轮转顺序与表格不符** | 灯带表顺序被改过 | 以 `g_dbg_ws_scan_idx` 为准记录，并同步更新本文档表格 |
| **退出后只有一条亮红/蓝** | 正常现象 | `light.c` 还是主机版灯效（`LIGHT_LOCAL_STRIP_MASK` 只含索引 0），S6 整体替换为从机图案 |
| **自检期间某条闪烁** | 该条 DMA 被重复启动（少见）| Watch `dma_busy`，检查 `bsp_ws2812_refresh_all` 的 busy/dirty 与帧完成回调 |

## 七、验收（工具可用即可，不是阶段 DoD）

- [ ] `DEBUG_TEST_MODE=1` 编出的调试固件能上电自检、每 2s 换一条、`g_dbg_ws_scan_idx` 随之变化
- [ ] 5 条实接灯带逐条能点亮（若某条异常，按第六节定位并记录）
- [ ] `DEBUG_TEST_MODE=0` 恢复正常灯色
- [ ] **没有与老口径不符的地方 → 配置一处都不用改**（只有发现不符才按第五节回填）
