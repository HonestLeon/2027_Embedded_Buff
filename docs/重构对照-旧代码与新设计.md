## 0. WS2812 驱动原理（以老代码为标本）

### 0.1 灯珠协议：单线归零码

WS2812 是**单线级联** LED：一根数据线串到底，每颗灯从数据流里"吃掉"属于自己的 24 bit，
把剩下的原样转发给下一颗。协议要点：

**（1）数据是归零码（NZR），不是电平不是 UART**——信息编码在**高电平的持续时间**里：

```
"0" 码：  ┌──┐                    高电平 ~0.4µs + 低 ~0.85µs
          │  │____________________

"1" 码：  ┌────┐                  高电平 ~0.8µs + 低 ~0.45µs
          │    │__________________

          <── 1.25µs 整 ──>       每个码总周期固定（这就是"归零"）
```

即：**每个 bit 就是一个固定周期的方波，区别只在占空比**（0 码≈30%，1 码≈64%）。
这个特性正是能用 PWM 驱动的根本原因。

**（2）颜色格式 GRB，高位先行**：每颗灯 24 bit = G7..G0, R7..R0, B7..B0
（G 在最前，WS2812 的历史遗留，软件必须按这个顺序发）。

**（3）复位帧**：连续 **>50µs 低电平** 表示一帧结束，所有灯锁存显示。
之后才能发下一帧。

**（4）不可寻址、不可中断**：整串数据必须是**连续无间隙**的一串波形，
中间断了超过复位时间整串就错误锁存。这就是为什么必须用 DMA 搬运而不是 CPU
逐位翻转——1.25µs 一个 bit，CAN 中断稍微一扰波形就废了。

### 0.2 驱动核心思想：PWM 周期 = 1 bit

老代码没有用 SPI，也没有手动翻转 GPIO，而是：

> **把一个 PWM 通道的周期配成恰好 1 bit 的时长（1.25µs），然后用 DMA 持续改写比较寄存器
> CCR——CCR = 10 就是"0"码，CCR = 25 就是"1"码。**

时序推导（对照老 `tim.c` 的 PSC=2, ARR=34）：

```
定时器时钟   = 84MHz（APB1 42MHz ×2，APB1 分频≠1 自动倍频）
计数频率     = 84MHz / (PSC+1) = 84/3 = 28MHz    → 每 tick ≈ 35.7ns
PWM 周期     = (ARR+1) × tick = 35 × 35.7ns = 1.25µs = 800kHz ✓
"0" 码占空比 = CCR=10  → 高电平 10 tick = 357ns（规格 0.4µs±150ns ✓）
"1" 码占空比 = CCR=25  → 高电平 25 tick = 893ns（规格 0.8µs±150ns ✓）
```

（对应 `WS2812.c` 开头：`T0H = 10; T1H = 25;`）

**ARR 与 CCR 的分工（最容易混淆的点）**：

| 寄存器 | 决定什么 | 谁写 | 共享吗 |
|---|---|---|---|
| ARR（自动重装） | PWM **周期**（1.25µs = 1 bit 时长） | 初始化写一次 34，之后**无人再碰** | 每定时器一个，通道共享 |
| CCR（比较寄存器） | **占空比**（CCR=10→"0"码，=25→"1"码） | **DMA 全程在写的就是它** | **每通道独立**（CCR1/2/3/4） |

同一 TIM3 上 CH1/CH2/CH4 三条灯带**共享同一个 1.25µs 节拍**（所以 bit 率都是
800kHz），但各自 CCR 值不同 → 占空比不同 → 三路输出的 0/1 序列互不相干——
这就是一块定时器能同时驱动三条内容不同的灯带的原因。
每个 DMA 流的外设地址被焊死在各自通道的 CCR 上（`PeriphInc=Disable`），
按 1.25µs 一个的节奏把缓冲区值逐个倒入；CCR 开了预装载，写入值在下一个
PWM 周期生效——一个值正好对应一个 bit。
若有人改 ARR，bit 时长就变了，整条灯带时序崩坏——所以 ARR 永远不动。

运行时的样子：

```
CCR 寄存器:   ← DMA 每 1.25µs 灌一个新值
   ... 25 10 10 25 25 10 ... 0 0 0 0 0 0 ...

输出波形:     ┌─┐ ┌┐ ┌┐ ┌─┐ ┌─┐ ┌┐          ┌─────
              │1│ │0│ │0│ │1│ │1│ │0│ ...    │ 低(复位)
              ─┘ ─┘ ─┘ ─┘ ─┘ ─┘
              <─ 24bit = 一颗灯 ─> <─ 复位段，全部锁存显示 ─>
```

DMA 工作在 **Normal 模式、半字宽、内存递增**：把整个缓冲数组按顺序灌进 CCR，
搬完自动停。缓冲末尾放一段 0（CCR=0 → 输出恒低），自然形成复位段。

### 0.3 老代码的数据结构与展开函数

```c
// WS2812.h —— 每条灯带一个大数组
#define WS2812_LED_NUM_1 (92)     // 下
#define WS2812_LED_NUM_2 (262)    // 中
#define WS2812_LED_NUM_3 (88)     // 上
#define WS2812_LED_NUM_4 (256)    // 灯臂
#define WS2812_Reset_NUM (50)

// WS2812.c —— 一个 LED 占 24 个 uint16 槽位，外加复位段
uint16_t LED_ROAD_1[WS2812_LED_NUM_1*24 + WS2812_Reset_NUM] = {0};
```

**关键理解：这个数组存的不是"颜色"，是"每一个 bit 对应的 CCR 值"**。
92 颗灯 = 2208 个 bit 槽 + 50 个复位槽。数组全局初始化为 0，所以复位段永远是低电平。

展开函数 `WS_2812_Set_RGB()` 把一个 RGB 颜色"翻译"进这 24 个槽位：

```c
void WS_2812_Set_RGB(uint16_t *ARR, uint16_t Start_Num, uint16_t C_Num,
                     uint8_t R, uint8_t G, uint8_t B)
{
    for (i = 0; i < C_Num; i++)           // 逐颗灯
    {
        for (j = 7; j >= 0; j--)          // G 通道，高位先行
            ARR[(Start_Num+i)*24 + j] = G & (0x1<<j) ? T1H : T0H;
        for (j = 7; j >= 0; j--)          // R 通道
            ARR[(Start_Num+i)*24 + 8 + j]  = R & (0x1<<j) ? T1H : T0H;
        for (j = 7; j >= 0; j--)          // B 通道
            ARR[(Start_Num+i)*24 + 16 + j] = B & (0x1<<j) ? T1H : T0H;
    }
}
```

逻辑：对每个颜色字节从 bit7 到 bit0 逐位判断，1 填 `T1H(25)`，0 填 `T0H(10)`。
三重循环按 **G→R→B** 顺序填，正好是 WS2812 要求的 GRB 高位先行。

发送就一行：

```c
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_1, (uint32_t *)LED_ROAD_3,
                      WS2812_LED_NUM_3 * 24 + WS2812_Reset_NUM);
```

DMA 从数组头搬到数组尾（共 `灯数×24+50` 个半字），硬件自动按 800kHz 连发，
搬完停。**CPU 全程零参与**。

### 0.4 老代码的完整运行流程（主从行为不一样）

**从机**（`slave/main.c` 主循环，每圈 `HAL_Delay(200)`）：

```
while(1):
    Decode()                    // 解 CAN，更新 state/color
    按 state 选图案:
        state=2  → Buff_Activatable() + Buff_Arrowhead_Flowing()  // 待激活呼吸箭头
        state=3  → Buff_Activating(circle_num)                    // 按环数点亮对应弧段
        state=4  → 全亮
    ↓ 以上图案函数都只是改写 LED_ROAD_x[] 数组
    HAL_TIM_PWM_Start_DMA(...) × 5   // 五条灯带全部重新发送
    HAL_Delay(200)
```

**主机**（`master/main.c`）：只在**上电初始化时**调用了一次 `WS_2812_Set_RGB`
（整条全红或全蓝）+ 4 路 `Start_DMA`，之后主循环里**再也没碰过灯带**。

### 0.5 图案函数：标定数据藏在魔数里

`WS2812.c` 后半部分是纯"画图"代码，核心是**灯带物理布局的标定表**。例如环数显示：

```c
void Buff_Activating(uint8_t circle)   // 灯带2上按环数点亮一段弧
{
    case 10: WS_2812_Set_RGB(LED_ROAD_2,   0, 49, ...); break;  // 10环: 第0~48颗
    case  9: WS_2812_Set_RGB(LED_ROAD_2,  49, 45, ...); break;  // 9环:  第49~93颗
    case  8: WS_2812_Set_RGB(LED_ROAD_2,  94, 39, ...); break;  // ...
    ...
    case  1: WS_2812_Set_RGB(LED_ROAD_2, 258,  4, ...); break;  // 1环:  最后4颗
}
```

这些 `0/49/94/258` 就是靶盘上一圈圈 LED 的起始编号——灯带是螺旋贴的，
一个环对应连续一段。`Buff_Activatable()`（待激活图案）里那 20 行零散的
`WS_2812_Set_RGB(LED_ROAD_2, 12, 2, ...)` 则是点亮靶面图案的特定几个点。
**这些数字是逐颗数出来的标定值，重构必须原样继承**（第 9 节核对表）。

### 0.6 老代码的问题与重构要点

理解了原理，老代码每个"史点"都能对号入座：

| # | 问题 | 后果 | 重构对策（详见第 1/2 节） |
|---|---|---|---|
| 1 | **主机上电只刷一次，主循环从不更新灯带** | 拨码改红蓝后灯不变（"先通电再改开关保持蓝色不变"bug 的直接原因） | 主机也要有刷新任务 |
| 2 | **从机每圈无条件重启 5 路 DMA** | 上一帧 DMA 还没搬完就 Start，波形从头错位重发 → 颜色错乱（"R 标紫色"类故障的病根） | `busy`/`dirty` 标志：搬完且有新内容才发 |
| 3 | **复位段只有 50 bit = 62.5µs**，规格要求 >50µs | 裕量极小，电源纹波/温漂下可能个别灯不锁存（"灯臂下半段不亮"的候选原因） | 复位段加到 90 bit（112µs） |
| 4 | `WS_2812_ADD_Reset()` 里 `memset(..., WS2812_Reset_NUM)` | **字节数错了**——缓冲是 uint16，应 memset 2×N 字节。幸而数组全局为 0 且这函数没人调，才没爆 | 重写时删掉或修正 |
| 5 | 图案函数直接操作 DMA 缓冲 + 魔数偏移 | 图案层和驱动层耦合，换灯带布局要翻遍代码 | 分两层：RGB 逻辑帧缓冲 + 发送时翻译成 CCR 值 |
| 6 | 亮度只有 0/255/10 三档，红蓝只能纯色 | 灯效单一 | 新驱动天然支持任意 RGB |

**新驱动的目标形态**：

```
图案层（config_light.h 表 + light.c）  驱动层（bsp_ws2812.c）
只操作 uint8 rgb[] 逻辑缓冲       持有 uint16 ccr_buf[] DMA 缓冲
    │ 改完置 dirty                       ↑ 发送前把 RGB 翻译成 CCR 序列
    ▼                                    │
刷新任务: 对每条 strip —— !busy && dirty ?
    → 翻译 + HAL_TIM_PWM_Start_DMA + busy=1
DMA 完成中断 → 只清 busy=0（无需 Stop_DMA：HAL Normal 模式已复位通道）
```

一句话总结老驱动的逻辑：**"把每个 bit 的占空比预先算好排进数组，让 PWM+DMA 硬件自动
播完一帧；图案就是往数组的特定区段填 10 或 25。"** 思路完全正确且值得继承，
缺的只是刷新调度（busy/dirty）和分层。

## 1. WS2812 驱动层

### 1.1 缓冲区定义

**老代码**（`WS2812.h` / `WS2812.c`）：

```c
#define WS2812_LED_NUM_1 (92)     // 下
#define WS2812_LED_NUM_2 (262)    // 中
#define WS2812_LED_NUM_3 (88)     // 上
#define WS2812_LED_NUM_4 (256)    // 灯臂
#define WS2812_Reset_NUM (50)

uint16_t LED_ROAD_1[WS2812_LED_NUM_1*24 + WS2812_Reset_NUM] = {0};  // 扇心外部
uint16_t LED_ROAD_2[WS2812_LED_NUM_2*24 + WS2812_Reset_NUM] = {0};  // 外部扇叶
uint16_t LED_ROAD_3[WS2812_LED_NUM_3*24 + WS2812_Reset_NUM] = {0};  // 扇心内部
uint16_t LED_ROAD_4[WS2812_LED_NUM_4*24 + WS2812_Reset_NUM] = {0};  // 灯臂
```

**问题**：
- ① 数组直接存 **CCR 值**（每个 bit 一个 uint16 槽），图案代码直接在 CCR 层作画 → 驱动与图案强耦合；
- ② 复位段 50 bit = 62.5µs，规格要求 >50µs，裕量太小；
- ③ 硬编码 4 条灯带，没有"一条灯带"的抽象，主从两份代码还各写一份。

**新设计**（`bsp/bsp_ws2812.h`）：

```c
#define WS2812_RESET_BITS  90u          /* 90bit × 1.25µs = 112µs > 50µs 规格 */

typedef struct {
    TIM_HandleTypeDef *tim;             /* 绑定的定时器            */
    uint32_t           channel;         /* PWM 通道                */
    uint16_t           led_num;         /* 灯数                    */
    uint16_t          *ccr_buf;         /* DMA 缓冲: led_num*24 + RESET_BITS */
    uint8_t           *rgb;             /* 逻辑帧缓冲: led_num*3 (GRB 字节序) */
    uint8_t            ch_idx;          /* htim->Channel 匹配用, init 时:
                                          ch_idx = 1u << ((uint32_t)channel >> 2)
                                          ⚠ 不是 (channel>>2)+1 —— ACTIVE_CHANNEL_x
                                          编码是 0x01/0x02/0x04/0x08(位掩码式,
                                          见 hal_tim.h L324~328) */
    volatile uint8_t   dma_busy;        /* DMA 正在发送            */
    volatile uint8_t   dirty;           /* 逻辑缓冲有新内容待发    */
} ws2812_strip_t;

void ws2812_init(ws2812_strip_t *s, TIM_HandleTypeDef *tim, uint32_t ch,
                 uint16_t led_num);
void ws2812_set_rgb(ws2812_strip_t *s, uint16_t start, uint16_t count,
                    uint8_t r, uint8_t g, uint8_t b);   /* 改 rgb 缓冲, 置 dirty */
void ws2812_fill(ws2812_strip_t *s, uint8_t r, uint8_t g, uint8_t b);
void ws2812_refresh_all(void);                          /* 主循环调用, 见 1.4 */
```

- ② 复位段 90 bit（112µs），顺手修裕量问题；
- ③ 一条灯带 = 一个 `ws2812_strip_t` 实例，主从共用驱动，实例表不同。

实例表（主机版，灯数沿用旧固件口径，TIM4_CH3 待核实后补）：

```c
/* bsp_ws2812.c —— 与《主机CubeMX配置清单.md》1.5/1.6 节一一对应 */
ws2812_strip_t strips[WS2812_STRIP_NUM] = {
    /*  tim      channel         led   说明(旧固件口径) */
    { &htim3, TIM_CHANNEL_1,   88, ... },   /* PA6  上灯带  */
    { &htim3, TIM_CHANNEL_2,  262, ... },   /* PA7  中灯带  */
    { &htim3, TIM_CHANNEL_4,  256, ... },   /* PB1  灯臂    */
    { &htim4, TIM_CHANNEL_1,  120, ... },   /* PB6  侧灯臂(从机用) */
    { &htim4, TIM_CHANNEL_2,   92, ... },   /* PB7  下灯带  */
    { &htim4, TIM_CHANNEL_3,  ... ,... },   /* PB8  丝印上灯带, 灯数待核实 */
};
```

### 1.2 颜色展开函数

**老代码**（`WS_2812_Set_RGB`，逐位填 CCR）：

```c
void WS_2812_Set_RGB(uint16_t *ARR, uint16_t Start_Num, uint16_t C_Num,
                     uint8_t R, uint8_t G, uint8_t B)
{
    for (i = 0; i < C_Num; i++) {
        for (j = 7; j >= 0; j--)
            ARR[(Start_Num+i)*24 + j]      = G&(0x1<<j) ? T1H : T0H;  // G 先行
        for (j = 7; j >= 0; j--)
            ARR[(Start_Num+i)*24 + 8 + j]  = R&(0x1<<j) ? T1H : T0H;
        for (j = 7; j >= 0; j--)
            ARR[(Start_Num+i)*24 + 16 + j] = B&(0x1<<j) ? T1H : T0H;
    }
}
```

**问题**：
- ① 三个循环体完全一样，只是偏移和颜色字节不同 → 复制粘贴式代码；
- ② 直接写 CCR 层，图案层被迫也操作 CCR 层。

**新设计**（保留"逐位查表"算法——它没有任何问题；只把**写入目标**从 CCR 缓冲改成 RGB 逻辑缓冲）：

```c
/* bsp_ws2812.c —— 逻辑层只存 RGB; 发送前才翻译成 CCR */
void ws2812_set_rgb(ws2812_strip_t *s, uint16_t start, uint16_t count,
                    uint8_t r, uint8_t g, uint8_t b)
{
    uint8_t *p = &s->rgb[start * 3u];
    while (count--) { p[0] = g; p[1] = r; p[2] = b; p += 3; }  /* GRB 字节序 */
    s->dirty = 1;
}
```

翻译（老逻辑原样保留，只是搬到发送时机执行）：

```c
static const uint16_t bit_ccr[2] = { T0H_CCR, T1H_CCR };   /* {10, 25} */

static void ws2812_translate(ws2812_strip_t *s)
{
    uint16_t *out = s->ccr_buf;
    const uint8_t *in = s->rgb;
    for (uint16_t led = 0; led < s->led_num; led++) {
        for (uint8_t byte = 0; byte < 3; byte++) {          /* G,R,B */
            uint8_t v = in[led*3 + byte];
            for (int8_t bit = 7; bit >= 0; bit--)
                *out++ = bit_ccr[(v >> bit) & 1u];          /* 高位先行, 老算法原样 */
        }
    }
    for (uint16_t k = 0; k < WS2812_RESET_BITS; k++)        /* 复位段保持全 0 */
        *out++ = 0;
}
```

> 算力核算：698 灯 × 24 位 ≈ 1.7 万次写，168MHz 下 <0.2ms，比一次 CAN 收发还便宜，实时放主循环毫无压力。

### 1.3 发送触发方式

**老代码·主机**（`main.c` 初始化段，全工程仅此一处）：

```c
/* 上电设一次全红/全蓝, 之后主循环再也不碰灯带 */
WS_2812_Set_RGB(LED_ROAD_1, 0, WS2812_LED_NUM_1, 255, 0, 0);
...
HAL_TIM_PWM_Start_DMA(&htim4, TIM_CHANNEL_2, (uint32_t*)LED_ROAD_1, ...);
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_2, (uint32_t*)LED_ROAD_2, ...);
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_1, (uint32_t*)LED_ROAD_3, ...);
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_4, (uint32_t*)LED_ROAD_4, ...);
```

**老代码·从机**（`main.c` 主循环末尾，每圈无条件重发）：

```c
/* 每圈(约200ms)无条件重启全部 5 路 DMA */
HAL_TIM_PWM_Start_DMA(&htim4, TIM_CHANNEL_2, (uint32_t*)LED_ROAD_1, ...); // 下
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_2, (uint32_t*)LED_ROAD_2, ...); // 中
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_1, (uint32_t*)LED_ROAD_3, ...); // 上
HAL_TIM_PWM_Start_DMA(&htim3, TIM_CHANNEL_4, (uint32_t*)LED_ROAD_4, ...); // 灯臂
HAL_TIM_PWM_Start_DMA(&htim4, TIM_CHANNEL_1, (uint32_t*)LED_ROAD_5, ...); // 灯臂一侧
```

**问题（本次重构的二号 bug 根源）**：
- 主机：**刷一次就不刷了** → 拨码切红蓝后灯不变（对应《大符思路》"先通电再改开关保持蓝色不变"）；
- 从机：**无条件重启**——若上一帧 DMA 尚未搬完（一帧 262 灯 = 8.2ms，加上 200ms 主循环里
  图案函数耗时，完全可能撞上），`Start_DMA` 会让波形从头错位重发 → 颜色错乱。
  《大符思路》记载的"R 标紫色""先改开关再通电显示异常"与此直接相关；
- 两台板子各自手写一套发送调用，将来加第 6 条灯带要改两处。

**新设计**（`bsp_ws2812.c`，busy/dirty 双标志 + DMA 完成回调）：

```c
/* 主循环调用, 无阻塞 */
void ws2812_refresh_all(void)
{
    for (uint8_t i = 0; i < WS2812_STRIP_NUM; i++) {
        ws2812_strip_t *s = &strips[i];
        if (s->dma_busy || !s->dirty)     /* 关键: 忙则跳过, 空闲且有新内容才发 */
            continue;
        ws2812_translate(s);              /* RGB -> CCR 序列 */
        s->dirty    = 0;
        s->dma_busy = 1;
        HAL_TIM_PWM_Start_DMA(s->tim, s->channel, (uint32_t*)s->ccr_buf,
                              s->led_num * 24u + WS2812_RESET_BITS);
    }
}

/* DMA 传输完成 —— 由 bsp_ws2812.c 覆盖 __weak 弱函数实现 */
void HAL_TIM_PWM_PulseFinishedCallback(TIM_HandleTypeDef *htim)
{
    for (uint8_t i = 0; i < WS2812_STRIP_NUM; i++) {
        ws2812_strip_t *s = &strips[i];
        /* ⚠ 必须同时匹配 tim 和 ch_idx: TIM3 上挂了 3 条灯带, 只看 htim 分不清
           是谁发完的。HAL 在调回调前已把完成通道写入 htim->Channel
           (TIM_DMADelayPulseCplt 源码已核实, F4 V1.28.x) */
        if (s->dma_busy && s->tim == htim && s->ch_idx == htim->Channel) {
            s->dma_busy = 0;   /* 释放, 允许下一帧。无需 Stop_DMA:
                                  HAL 在 Normal 模式已于回调前把通道状态复位为 READY
                                  (已核对本工程 hal_tim.c 源码); DMABurstState 与
                                  PWM Start_DMA 路径无关, 不需要动 */
        }
    }
}
/* ws2812_init 里: s->ch_idx = 1u << ((uint32_t)channel >> 2);
   ⚠ htim->Channel 的 ACTIVE_CHANNEL_x 编码是 0x01/0x02/0x04/0x08(位掩码式,
   见 hal_tim.h L324~328), 不是 1/2/3/4 —— 早期文档的 (channel>>2)+1 是错的 */
```

> 对比：老代码"重启撞车"在这套机制下**结构上不可能发生**——busy 期间永远不会 Start。
> 每条灯带一帧最长 262 灯 = 8.2ms，图案刷新周期 200ms，吞吐余量 20 倍以上。

### 1.4 老代码的死代码与 bug

**老代码**（`WS2812.c`）：

```c
void WS_2812_ADD_Reset(uint16_t *ARR, uint16_t Start_Num)
{
    memset(ARR + Start_Num*24, 0, WS2812_Reset_NUM);   /* ← BUG */
}
```

**问题**：缓冲是 `uint16_t`，`memset` 第三参是**字节数**，应为 `2*WS2812_Reset_NUM`。
现在只清了一半——但数组全局初始化为 0 且该函数从未被调用，所以没炸。
属于"埋着的雷"。

**新设计**：复位段在 `ws2812_translate()` 末尾统一清零（见 1.2），该函数不再需要；
另外老 `WS2812.c` 里 `load_num_1~5`、被注释掉的 `Buff_Unactivated_Internal` 旧版本、
`Buff_Heart` 等未使用函数一并清理，标定值全部收进图案层（见第 2 节）。

```c
/* 模板表化：表在 config_light.h，渲染在 application/light.c（草图） */
static const uint16_t arrowhead_template[4][2] = {   /* 每行{起始,宽度}, 老代码原值 */
    { 3, 2}, {10, 4}, {17, 2}, {21, 2},              /* + {24,2}{30,2} 交错, 照搬 */
};
void buff_pattern_arrowhead_tick(ws2812_strip_t *s, uint8_t r, uint8_t g, uint8_t b)
{
    static uint8_t phase = 0;                        /* 动画相位自持, 无需外部喂 */

    for (int8_t off = -phase; off < (int8_t)s->led_num/8 + 4; off += 4)
        buff_arrowhead_draw(s, off, r, g, b);        /* 老模板绘制逻辑 */
    phase = (phase + 1) & 3;
}
/* 由 4Hz 逻辑帧调用 → 动画速度天然与帧频解耦 */
```

### 3.2 新设计（`application/buff.c` 的从机状态机段 + `application/hit_detect.c`）

> 下面是设计草图，函数/变量名以实际实现为准：从机沿用与主机**同一份协议段**，
> 只把《代码架构设计》3.3 里标注"主机构建专用"的状态机段整段换成从机状态机
> （阶段划分与逐文件改动见 `docs/从机重构清单.md` 第三节）。

```c
typedef enum { SLV_SLEEP, SLV_ARMED, SLV_ACTIVATED, SLV_ALL_ON } slave_state_t;

/* 状态机: 单入口, 每状态一个 handler, 由 4Hz 逻辑帧驱动 */
static void slave_fsm_step(void)         /* 4Hz 调用 */
{
    switch (fsm.state) {
    case SLV_SLEEP:      on_sleep();      break;
    case SLV_ARMED:      on_armed();      break;    /* 待激活图案, 动画自持 */
    case SLV_ACTIVATED:  on_activated();  break;    /* 环数显示 + 回报主机 */
    case SLV_ALL_ON:     on_all_on();     break;
    }
}

/* 转换只在三处发生, 全部经这一个函数, 便于打断点/加日志 */
static void fsm_goto(slave_state_t s)
{
    if (fsm.state == s) return;
    pattern_clear_all();                     /* 统一清屏, 替代散落的 last_state 判断 */
    fsm.state = s;
}
```

| `last_state` + 清屏 if | `fsm_goto()` 统一清屏 |

| `start_countt` / `start` | 删除（来源不明的补丁变量） |
| `HAL_Delay(200)` | TIM6 1ms tick → 4Hz 逻辑帧分频 |
| 每圈 5 路 Start_DMA | `ws2812_refresh_all()` dirty 机制 |

### 4.2 新设计（`application/buff.c` + `Core/Src/stm32f4xx_it.c`，✅ 已按此实现）

> 早期设想是"中断只置标志 + 主循环消费"；实现时改为**调度器直接跑在 TIM6 中断里、
> 主循环保持为空**（原因见《代码架构设计》第二节：`bsp_ws2812` 刷新若在**主循环与中断两处**
> 启动会有"同时 Start_DMA"的并发竞争；CAN 收发同理）。下面是实际节拍：

```c

if (++sw_div >= SWITCH_POLL_DIV)        /* 20ms: 拨码采样(消抖) + 电机模式 */

{ buff_step();   /* 排空 bsp_can1_pop → 事件 → 状态转换 → 发 0x161 */ light_tick(); }

/* main.c 的 USER CODE WHILE 保持空转；初始化序列见《代码架构设计》四.3 */
```

## 5. CAN 收发

### 5.1 过滤器与配置

**老代码**（`bsp_can.c can_filter_init`）：4 组过滤器 × IDLIST 模式，16 个 ID 硬编码；
`can_config.h` 里还有摩擦轮/拨弹/Yaw/Pitch 等**从别的项目拷来的 ID**（本工程无这些外设）。

**新设计**（`bsp/bsp_can.c`）：

```c
/* 两个 CAN 各一组过滤器, MASK 模式收 0x160~0x161 */
static void can_filter_config(CAN_HandleTypeDef *hcan)
{
    CAN_FilterTypeDef f = {
        .FilterMode           = CAN_FILTERMODE_IDMASK,
        .FilterScale          = CAN_FILTERSCALE_32BIT,
        .FilterIdHigh         = 0x160 << 5,     /* 标准ID, 左对齐 */
        .FilterMaskIdHigh     = 0x7F8 << 5,     /* 只比高 7 位 → 收 0x160/0x161 */
        .FilterFIFOAssignment = CAN_RX_FIFO0,
        .FilterActivation     = ENABLE,
        .SlaveStartFilterBank = 14,
    };
    HAL_CAN_ConfigFilter(hcan, &f);
}
/* Start + ActivateNotification(RX_FIFO0) 在 bsp_can_start() 里 */
```

**老代码**（`HAL_CAN_RxFifo0MsgPendingCallback` → `MotorReceive`）：

## 6. 击打检测 EXTI

**老代码**（`slave/gpio.c` EXTI 回调）：

```c
void HAL_GPIO_EXTI_Callback(uint16_t GPIO_Pin)
{
    if (start == 0) { start = 1;               /* 来源不明的启动补丁 */
        if (once == 0 && state == 2) {          /* once/state 全局变量直读 */
            last_state = 0;
            if      (GPIO_Pin == RDET1_Pin) { once=1; circle_num=10; state=3; ... }
            else if (GPIO_Pin == RDET2_Pin) { once=1; circle_num= 9; state=3; ... }
            else if (GPIO_Pin == RDET3_Pin) { once=1; circle_num= 8; state=3; ... }
            else if (GPIO_Pin == RDET4_Pin) { once=1; circle_num= 7; state=3; ... }
            else if (GPIO_Pin == RDET5_Pin) { once=1; circle_num= 6; ... }
            ... RDET6~10 继续复制粘贴 ...
        }
    }
}
```

**问题**：
- ① 十路 if-else 复制粘贴，环数表埋在分支里；
- ② 中断里直接改业务状态（`state=3`）并清标志，逻辑分散；
- ③ `once` 三态语义（0=可击发 1=已击发 2=待复位）只有作者知道。

**新设计**（`application/hit_detect.c`，从机构建）——中断置记录，任务里查表：

```c
/* 引脚→环数 标定表: 与老代码 RDET1~5→10..6 完全一致, 勿改 */
static const struct { uint16_t pin; GPIO_TypeDef *port; uint8_t circle; } hit_map[] = {
    { KEY1_Pin,  KEY1_GPIO_Port, 10 }, { KEY2_Pin,  KEY2_GPIO_Port, 9 },
    { KEY3_Pin,  KEY3_GPIO_Port,  8 }, { KEY4_Pin,  KEY4_GPIO_Port, 7 },
    { KEY5_Pin,  KEY5_GPIO_Port,  6 }, /* KEY6~10 同理, 按机械标定 */
};

/* EXTI 回调: 只记时间戳 */
void HAL_GPIO_EXTI_Callback(uint16_t pin)
{
    for (uint8_t i = 0; i < HIT_CH_NUM; i++)
        if (hit_map[i].pin == pin) {
            hits[i].timestamp = dwt_us();
            hits[i].pending   = 1;
        }
}

/* 逻辑帧任务: 查表 + 显式击发状态 */
void hit_detect_task(void)
{
    for (uint8_t i = 0; i < HIT_CH_NUM; i++) {
        if (!hits[i].pending) continue;
        hits[i].pending = 0;
        if (hd.state == HD_ARMED) {           /* 只在待激活态接受击打 */
            hd.state = HD_FIRED;
            hd.circle = hit_map[i].circle;    /* 环数来自表, 不来自 if-else */
            fsm_goto(SLV_ACTIVATED);
        }
        /* HD_FIRED / HD_LOCKED: 忽略, 老代码 once=1/2 的语义显式化 */
    }
}
```

### 6.3 完整环数标定表（老代码原文，**必须台架复核**）

| 中断引脚 | 板级引脚 | 老代码 `circle_num` | 说明 |
|---|---|---|---|
| RDET1 | PA1 | **10** | 最外环 |
| RDET2 | PA2 | 9 | |
| RDET3 | PA3 | 8 | |
| RDET4 | PA4 | 7 | |
| RDET5 | PA5 | 6 | |

### 6.4 老代码的三个隐式机制（新实现要保留语义）

| 机制 | 老实现 | 语义 |
|---|---|---|
| `once` | `0`=可击发 → `1`=已击发 → `2`=打错(待上报复位) | 一次激活只接受**一次**击打；进入休眠(`state=1`)时清 0 = **重新武装** |
| `start` + `start_countt` | 首次中断置 `start=1`；主循环里数到 2 次（≈400ms）才清 0 | 中断**时间锁存**：约 400ms 内的后续中断被忽略（防连击抖动） |
| 打错的判定 | **中断发生在"非 `once==0 && state==2`"时** → `once=2` | 即"打了没点亮的板子 / 已在激活态的板子" → 主循环上报 `[2]=0x01` 并回休眠 |

> 这三者合起来实现了规则里的"**击中非随机点亮的装甲模块 → 激活失败**"，
> 新实现建议做成显式状态：`HD_ARMED / HD_FIRED / HD_LOCKED / HD_MISHIT`。

## 8. 定时与随机数

**老代码**：

```c
/* SysTick 里塞业务计数 */
void SysTick_Handler(void) { HAL_IncTick(); TIM_Counter++; }   /* 1ms 基准(能用但脏) */

/* 三套随机种子混用 */
srand(1);                                  /* main 里, 调试遗留, 写死! */
srand(CNT_my);                             /* 小符: 用主循环计数器做种子 */
srand(random_seed);                        /* 大符: TIM2 5Hz 中断里 random_seed+=7 */
DWT_GetDeltaT(&CNT_my);                    /* dt 补偿 */
```

**问题**：
- `srand(1)` → 每次上电序列相同（体育道德问题 :)）；
- 三套种子三处喂，谁也不知道最终随机性来自哪；
- TIM2 专门为 `random_seed+=7` 存在，浪费一个定时器。

**新设计**：

```c
/* 上电一次 */
uint32_t seed;
HAL_RNG_GenerateRandomNumber(&hrng, &seed);
srand(seed);
/* 小符: generateUniqueRandomArray_SMALL_BUFF 算法原样收进 buff_random.c */
/* 大符: generateUniqueRandomArray_BIG_BUFF 算法原样收进 buff_random.c      */
/*   (大符前后两次允许重复、第二块与第一块不重复的规则注释一并保留)          */
/* dt: 由 TIM6 节拍保证恒定, DWT 仅保留给超时测量等低频用途 */
```
