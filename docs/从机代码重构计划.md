# 从机代码重构计划（分阶段）

> 对象：`2027_Embedded_Buff_Slave/`（打符灯板固件）
> 依据：《从机重构清单.md》《代码架构设计.md》《能量机关规则.pdf》5.5.2.1
> 已确认的前置：**CubeMX 配置已完成并校验通过**（6 通道 PWM + 6 条 DMA 全部 `MEMORY_TO_PERIPH`、
> 10 路 EXTI、NVIC 优先级、CAN1=1Mbps+ART/ABOM、USER CODE 区保留）
> 目标：与主机同构的 `config / bsp / application` 分层；**复用主机框架，只换业务层**

---

## 一、总体策略

1. **最大化复用**：主机的 `config/bsp` 框架与 `application/buff.c` 的**协议段**已可直接继承，
   从机真正要新写的是 **`hit_detect`（击打采集）+ 从机状态机 + 灯板图案库**；
2. **口径继承（不标定）**：**硬件与 2025 完全相同** ⇒ 老从机的灯数（87/262/320/120/92）与
   "索引↔功能"映射**就是规格**，直接继承 `config_ws2812.h` / `config_light.h`；
   逐条点亮只作为**排障工具**保留（见《从机灯带自检与排障》），不再是必经阶段；
3. **自底向上，但阶段间不设台架闸门**：S3→S4→S5→S6 **一次性连续写完**，每阶段只过“静态可验项”
   （编译 0 error 0 warning、表/缓冲一致、与主机协议段 diff 一致、代码走查），
   **所有物理验证集中到 S7 一次做**（省反复烧录/上板；代价与对策见 §四 风险表末两行）；
4. **时序纪律**：从机必须 **1ms 级排空 CAN**（大符轮次切换的"熄灭/点亮"两帧仅隔 150ms），
   且**禁止 `HAL_Delay` 阻塞**（老从机 200ms 阻塞是"熄灭不稳定"的根因）；
5. **⚠ 从机板未接拨码开关**（实测）：PD2/PB3/PB4 悬空 + 内部上拉 → 三个 `SW_*` 恒为高（恒"激活"），
   因此**颜色/大小符一律取 CAN 帧**（[4]/[2]），**自检只能用 `DEBUG_TEST_MODE` 宏触发**
   （拿 `SW2` 当触发会一上电就永久扫描；`TEST_TRIGGER_USE_SW2` 已置 0）。
6. **测试方法（定死，不再讨论）**：主判据 = **实机观察**（灯带外观、该熄的熄没熄、进度条、环数）
   + Keil 调试器 **Watch 全局变量/结构体快照**；**CAN 分析仪 / CAN 盒不进计划、不作任何阶段判据**。
   配套要求：**每阶段必须交付一个可 Watch 的快照结构体**，S7 只靠变量就能分层定位——
   `S3=g_buff_rx`✅ / `S4=g_dbg_hit` / `S5=g_dbg_slv` / `S6=g_dbg_pat`；对外发帧一律用**真主机**（或 5 板联机）。

```
S0 基线 ──► S1 config ──► S2 口径继承(✅无需标定)
                                  └─►╒══════ 连续编码块：阶段间不上台架 ══════╕
                                     ║ S3 bsp 适配  →  S4 hit_detect         ║

                                     ╘═══════════════╤═══════════════════════╛

```

### S3 bsp 复用与适配（0.5 天）—— ✅ S3.1 已实现(2026-10-06)，只剩台架验收

**S3 只有一处真正的代码改动 = S3.1（CAN 出队从 4Hz 挪到 1ms）✅ 已落地**；其余四项是做决定并记录，不改代码。

#### S3.1 设计决定（照此实现即可，不必再权衡）

| 项 | 决定 | 理由 |
|---|---|---|
| 谁在 1ms 里排空 | 在从机 `application/buff.c` 新增 `void buff_can_rx_poll(void)`，由 `it.c` 的 **1ms 段**调用 | "收帧→解析→更新目标状态"是业务层动作，`bsp_can` 只负责 pop；放进 `buff.c` 后 **S5 换从机状态机时这个函数原样保留**，主从两版的差异仍然只集中在"状态机那一段"，同步成本最低 |
| 排空后做什么 | 逐帧解析，**立刻覆盖目标状态**（`cmd` / 大小符 / 颜色 / `round`）并 `++事件计数`；**不做动画、不发上报** | 目标状态是幂等覆盖 → 主机"全亮"一次连发 5 帧也不会丢帧；熄灭帧在 1ms 内生效，才能满足 §四 的 150ms 两帧时序 |
| 4Hz 还做什么 | `buff_step()` 改为**消费事件槽**（不再自己调 `bsp_can1_pop`），只跑状态抬升 / 灯效动画 / 上报 | 动画需要 250ms 节拍；上报放 4Hz 与老从机语义一致（老从机也是主循环一轮报一次） |
| 队列要不要加深 | **不改**（CAN1 队列仍 16 帧） | 主机最坏突发 = 全亮 5 帧 + 每 250ms 一帧；1ms 排空后队列基本常空 |
| ISR 预算 | 已核算，安全 | 5 条主动灯带里最长 320 灯：`translate` 写 7680 个 `uint16` ≈ 0.18ms@168MHz；每 tick 最多启动 2 条 → 最坏一 tick ≈0.36ms；单条 DMA 发送 320×24×1.25µs ≈ **9.6ms**，5 条并行各自独立定时器 → 全部刷完 ≈12ms << 灯效周期 250ms。**从机 1ms 中断里没有电机环**，比主机宽裕得多 |

**S3 阶段内静态验收**（写完即过，不上台架）：`it.c` 的 1ms 段确实调用 `buff_can_rx_poll()`；
`g_buff_rx` 字段齐全（frames/bad_frames/seq/cmd/is_big/is_blue/panel_a/panel_b/round/age_ms/max_burst）；
从机构建内主机状态机不参与编译（`#if BOARD_ROLE_MASTER`）；语法检查 0 error 0 warning。
**物理判据全部移到 S7 第 1 组**（见 S7 的五组表）。

| # | 模块 | 改动 |
|---|---|---|
| S3.1 | `buff_can_rx_poll()` + `it.c` 1ms 调用 | ✅ **已实现**：从机 `buff.c` 新增接收路径（解析下行 `0x161` → 幂等覆盖目标状态 + `seq`/`frames`/`age_ms`/`max_burst`），`it.c` 在 1ms 段调用。**同时把主机状态机整段用 `#if BOARD_ROLE_MASTER` 在从机构建里关掉** —— 否则从机会每 250ms 往总线发 0x161 跟真主机抢话，还会在 4Hz 里 `bsp_can1_pop` 与 1ms 排空抢同一队列 |

| 组 | 实机看什么 | Watch 什么（主判据） | 对应 §六 |
|---|---|---|---|
| 1 收帧 | 点灯/熄灭/复位/全亮指令是否即时生效；大符轮次切换旧对确不熄 | `g_buff_rx.frames/seq` 随帧增长、`cmd`/`round` 等于本帧、`age_ms` 稳定 1~2、`bad_frames` 与 `bsp_can1_rx_drop_count()` 恒 0 | ⑥⑦⑪ |
| 2 击打 | 10 路逐路触发（短接 RDET1~10）、环数显示、休眠态/已激活态被击是否算打错 | `g_dbg_hit.fire_cnt/mishit_cnt/last_pin/last_circle/age_ms`（**重点：RDET9 到底几环**） | ②⑩ |
| 3 状态机 | 小符 5 块依次点亮→击中→下一块、打错复位、第二块起 2.5s；大符 5 组 + 首击 1s 窗口 + **旧两块确实熄灭** | `g_dbg_slv.state/round/panel/report_tx`（进 ACTIVATED 只报一次）；组 1 计数不清零 | ⑥⑨⑩⑫ |
| 4 外观 | 待激活图案 + 箭头流动、环数 1~10 段、进度条 n/5、全激活，逐条对照规则图 5-20/5-21/5-23 | `g_dbg_pat.strip/pattern/phase/progress`；亮度不对先查 `SLV_LEVEL_*`（位序陷阱见 §五 #14） | ①③④⑤⑧ |
| 5 收尾 | 5 块板同总线不串扰（逐块核板号）；连续 2h 无死机/花屏；出厂配置 | `g_sched_tick_cnt` 持续涨、drop 计数恒 0、`DEBUG_TEST_MODE=0` | ⑫⑬⑭ |

> **组 1 的发帧前提**（新解析比老 `Decode()` 严）：只有 ID=`0x161`、`[0]=0xAA`、
> `[1]∈{0x01,0x02,0x03,0x04}`、`[3]≤5` 且 `[5]≤5` 的帧才计入 `frames`/`seq`，其余进 `bad_frames`
> （老从机什么帧都吃，所以照老协议注释发 `[1]=0x00` 会“看起来没收到”）。排查顺序：
> `frames` 不涨 → 看 `bad_frames` → 看 `bsp_can1_rx_drop_count()` → 看 `g_sched_tick_cnt` 是否在动。

**放行规则**：组 1→5 串行，任一组不过就停在组内修复后整组复跑；组 5 烤机出现异常需回到对应组复查并在 §六 打勾处记现象。

## 四、风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| **RDET9 环数映射错误**（老代码疑为笔误，2 环无对应） | 2 环打不出来 / 环数显示错 | 标定表单一来源（只有 `hit_map[]` 一处）；逐路实测校正归 **S7 组 2**，短接 + Watch `g_dbg_hit` 即可，不用仪器 |
| **灯带通道与丝印错位**（主机板教训） | 灯效画错条 | 从机口径取老从机的 **DMA 绑定**（不是丝印、也不是主机版数值），`SLV_STRIP_*` 已逐条核对一致；真出现“某条不亮/段位不对”再用《从机灯带自检与排障》定位 |
| **PB8(TIM4_CH3) 接线** | 灯带表条数 | 已按老行为定案：老从机**从不驱动**该口 → `WS_LED_NUM_SPARE=0`（不分配/不发送）。若硬件确实与 2025 不符，改这一处宏即可 |
| **“全激活”外观无定论** | 与规则图不符 | S6 图案实现时按老从机口径先做 + 与队伍确认；**S7 组 4** 与规则图 5-23 实机对照 |
| **老从机 200ms 单缓冲缺陷** | 若沿用老结构，"熄灭"永远不稳定 | S3.1 已强制 1ms 排空 CAN（代码✅）；**S7 组 3** 专项验收旧对确不熄 |
| **灯数与实际不符** | 末端不亮/多亮 | 灯数继承老 `WS2812.h`(87/262/320/120/92)，正确性由“老固件整季实机运行”背书；若某条末端有残点，按《从机灯带自检与排障》点数后改 `WS_LED_NUM_*` 一处 |
| **5 块板程序烧错**（按板编译） | 灯板号错乱 | 固件文件名带板号；**S7 组 5** 联机时逐块核对 |
| **阶段间不上台架 → 缺陷集中在 S7 暴露** | 定位面大，返工挤占联调窗口 | ①每阶段静态可验项当闸门（编译/0 警告、表-缓冲一致、协议段 diff、代码走查）；②S3~S6 各留一个 Watch 结构体，S7 只看变量即可分层定位；③S7 五组严格按依赖串行，前组不过不开后组 |
| **不用 CAN 分析仪 → 缺帧级证据** | 协议扯皮时只能靠软件计数与现象 | 判据内建进固件：`g_buff_rx`(frames/bad_frames/age_ms/max_burst) + 收发 drop 计数 + `g_dbg_hit/slv/pat`；外观与熄灭类问题本就靠实机观察；真需帧级旁证按临时手段处理，不写进计划、不排期 |
