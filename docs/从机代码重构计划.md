# 从机代码重构计划（分阶段）

> 对象：`2027_Embedded_Buff_Slave/`（打符灯板固件）
> 依据：《从机重构清单.md》《代码架构设计.md》《能量机关规则.pdf》5.5.2.1
> 已确认的前置：**CubeMX 配置已完成并校验通过**（6 通道 PWM + 6 条 DMA 全部 `MEMORY_TO_PERIPH`、
> 10 路 EXTI、NVIC 优先级、CAN1=1Mbps+ART/ABOM、USER CODE 区保留）
> 目标：与主机同构的 `config / bsp / application` 分层；**复用主机框架，只换业务层**

---

## 一、总体策略

1. **最大化复用**：主机的 `config/bsp` 框架与 `application/buff.c` 的**协议段**已可直接继承，
   从机真正要新写的是 **`hit_detect`（击打采集）+ 从机状态机 + 灯板图案库**；
2. **标定先行**：开工第一件实事是**通道扫描**（S2）——它决定 `config_ws2812.h` 的灯带表与灯数，
   也是后面所有灯效的前提（主机板吃过"丝印与固件口径系统性错位"的亏）；
3. **自底向上**：config → 标定 → bsp → hit_detect → 状态机 → 图案 → 联调，每阶段有硬验收；
4. **时序纪律**：从机必须 **1ms 级排空 CAN**（大符轮次切换的"熄灭/点亮"两帧仅隔 150ms），
   且**禁止 `HAL_Delay` 阻塞**（老从机 200ms 阻塞是"熄灭不稳定"的根因）。

```
S0 基线确认 ──► S1 config 从机化 ──► S2 ★通道扫描标定 ──► S3 bsp 适配 ──► S4 hit_detect
                                                                    │              │
                                                                    └──► S5 从机状态机 ◄──┘
                                                                              │
                                                                        S6 灯板图案库
                                                                              │
                                                                        S7 联调与验收
```

### S1 config 从机化（0.5 天）


> **逐文件改动明细只在《从机重构清单》第三节维护**，本节不抄第二遍。

本阶段就四件事：① `BOARD_ROLE_MASTER=0` + 新增 `SLAVE_PANEL_NUM`(1~5)；
② 灯带表先按老从机口径填占位（S2 扫描后回填真值）；③ `config_light.h` 标定值**一个字不改**地继承；
④ 删 `config_motor.h`（从机无电机）。

**验收**：编译通过；`grep -rn "MOTOR_" application/ config/` 无残留引用（除已删文件）。

### S2 ★ 通道扫描与标定（1 天，**先做**）

| # | 任务 | 说明 |
|---|---|---|
| S2.1 | 补齐灯带缓冲 | `bsp/bsp_ws2812.c` 按 `WS2812_STRIP_TBL` 补回 5~6 对缓冲；核对 RAM（881 灯 ≈ **43KB**，必须放主 SRAM，**不能用 CCM**）|
| S2.2 | 通道扫描 | `DEBUG_TEST_MODE=1` 编译烧录 → 逐条白光 2s；Watch **`g_dbg_ws_scan_idx`** 记录"索引 ↔ 物理灯带 ↔ 灯数" |
| S2.3 | 确认 PB8 | 索引 5（TIM4_CH3）是否亮：亮 → 数灯数并填表；不亮 → `led_num=0` 并注释归档 |
| S2.4 | 回填 | 灯带表 + 灯数写回 `config_ws2812.h`；索引↔物理位置对照表写进注释与本文件 |
| S2.5 | 灯效归属确认 | 哪条是"靶面(中)"、哪两条是"灯臂(内/外)"、哪条是"进度条"——**决定 S6 图案画在哪条上** |

**验收**：每条实接灯带都能单独点亮；灯数确认；对照表回填完毕；`DEBUG_TEST_MODE=0` 后恢复正常灯色。

> ⚠️ 这一步的产出直接决定 S6 的图案实现，**不要跳**。

### S3 bsp 复用与适配（0.5 天）

| # | 模块 | 改动 |
|---|---|---|
| S3.1 | `bsp_can` | 逻辑复用；**把 CAN 出队从 4Hz 改到 1ms**（`bsp_can1_pop` 在 1ms 节拍里排空 → 只做"更新目标状态/置事件"），满足 150ms 熄灭间隔的时序要求 |
| S3.2 | `bsp_ws2812` | 复用（多灯带后 `refresh_all` 仍是"每 tick ≤2 条"，6 条全刷约 10ms << 灯效周期）|
| S3.3 | `bsp_switch` | 复用（20ms 采样/80ms 消抖）；从机用到的拨码：颜色、大小符、停转（停转在从机侧无意义，可只用颜色+大小符）|
| S3.4 | `bsp_rng` | 复用（从机其实不需要随机数——`BUFF_NUM` 是编译期常量；若无其它用途可在从机构建中不初始化 RNG，保留代码以备扩展）|
| S3.5 | `bsp_can` 的 CAN2 分支 | **保留**（从机不用电机总线，但 `bsp_can.c` 是主从共用；若要瘦身，用 `BOARD_ROLE_MASTER` 做条件编译——S3 阶段决定）|

**验收**：CAN 盒发一帧 `0x161` → 从机 1ms 内更新目标状态（用 Watch 观察状态变量，无 4Hz 延迟）。

---

### S4 hit_detect —— 击打采集与环数（1 天）

| # | 任务 | 说明 |
|---|---|---|
| S4.1 | 新建 `application/hit_detect.c/.h` | EXTI 回调只记录（引脚+时间戳+置位）；判定在任务里做 |
| S4.2 | 环数标定表 | `KEY1~10 → 10,9,8,7,6,5,4,3,?,?`；**⚠ RDET9 老代码写 1 环（疑为笔误，应为 2 环）→ S4.4 实测校正** |
| S4.3 | 显式状态 | `HD_ARMED → HD_FIRED → HD_LOCKED`，以及 `HD_MISHIT`；语义对齐老代码 `once`(0/1/2)+`start` 锁存 |
| S4.4 | 环数实测 | 逐一短接 RDET1~10，记录实际上报/显示环数，**重点核对 9/10 号**；回填标定表 |
| S4.5 | 打错判定 | "在非 ARMED 状态被击中" → `HD_MISHIT` → 通知状态机上报 `[2]=0x01` 并回休眠 |

**验收**：10 路逐一击打都能触发且环数正确；休眠状态下击打 → 上报打错；连续两次击打不会重复上报。

### S5 从机状态机（`buff.c` 换掉主机构建专用段）（1 天）


> 状态定义、解码规则（哪些命令看灯板号、哪些广播）、上报字节、打错处理与状态清理 ——
> **全部在《从机重构清单》§3.3 与 §七（协议速查）维护**，本处不重复。

两条最容易漏的：协议段（`buff_frame_pack/parse`、`buff_send_frame`、`buff_slave_report_parse`）
**逐字节不动**（主从共享真相源）；进入 `SLV_ACTIVATED` 的瞬间**只上报一次**。

**验收**：用 CAN 盒按 4Hz 发指令，Watch 状态变量，验证四个状态的进入/退出与上报时机（对照《从机重构清单》状态表）。

### S6 灯板图案库（`light.c` 换成从机图案）（1~1.5 天）


> 四种外观各画在哪条灯带、用哪张标定表、哪些是规则要求而老从机没做的 ——
> **在《从机重构清单》§3.5 与 §五（差异表 #1/#6）维护**。

| # | 任务 | 说明 |
|---|---|---|

| S6.2 | 进度条 | 主机已在下行帧 `[6]` 发 `round`，从机按它分段点亮中部灯臂（新增，规则要求） |

**验收**：四种状态外观与规则图 5-20/5-21/5-23 逐项对照；进度条随 `round` 递增 1/5→5/5；环数 1~10 逐一核对。

### S7 联调与验收（1 天）


> **逐项验收清单只有一处：《从机重构清单》§六（①~⑭，含台架、全流程、时序、5 板联机、烤机、归档）**。
> 本节只定本阶段的通过口径：

- 小符全流程（5 块依次点亮→击中→下一块，含打错复位、第二块起 2.5s）；
- 大符全流程（5 组、首击 1s 窗口、**轮次切换时旧的两块确实熄灭** <- 最关键的一条）；
- 时序：主机发帧 → 从机响应 ≤1ms；
- 5 块板同总线联机无串扰；2h 烤机无异常。

## 四、风险与依赖

| 风险 | 影响 | 缓解 |
|---|---|---|
| **RDET9 环数映射错误**（老代码疑为笔误，2 环无对应） | 2 环打不出来 / 环数显示错 | S4.4 逐一实测校正；标定表单一来源 |
| **灯带通道与丝印错位**（主机板教训） | 灯效画错条 | S2 强制通道扫描 + 记录对照表 |
| **PB8 是否接灯带未知** | 灯带表条数不确定 | S2.3 目视+扫描确认 |
| **"全激活"外观无定论** | 与规则图不符 | S6.5 对照规则图 + 与队伍确认 |
| **老从机 200ms 单缓冲缺陷** | 若沿用老结构，"熄灭"永远不稳定 | S3.1 强制 1ms 排空 CAN；S7.2 专项验收 |
| **灯数标定偏差** | 末端不亮/多亮 | S2.2 点数（主机 88 颗的经验：目测末端全亮为准）|
| **5 块板程序烧错**（按板编译） | 灯板号错乱 | 固件文件名带板号；S7.5 联机时逐块核对 |
