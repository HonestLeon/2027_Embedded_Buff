# 从机代码重构计划（分阶段）

> 对象：`2027_Embedded_Buff_Slave/`（打符灯板固件）
> 依据：《从机重构清单.md》《代码架构设计.md》《能量机关规则.pdf》5.5.2.1
> 已确认的前置：**CubeMX 配置已完成并校验通过**（6 通道 PWM + 6 条 DMA 全部 `MEMORY_TO_PERIPH`、
> 10 路 EXTI、NVIC 优先级、CAN1=1Mbps+ART/ABOM、USER CODE 区保留）
> 目标：与主机同构的 `config / bsp / application` 分层；**复用主机框架，只换业务层**

---

## 一、总体策略

1. **最大化复用**：主机的 `config/bsp` 框架与 `application/buff.c` 的**协议段**已可直接继承，
   从机真正要新写的是 **`hit_detect`（击打采集）+ 从机状态机 + 灯板图案库**；
2. **口径继承（不标定）**：**硬件与 2025 完全相同** ⇒ 老从机的灯数（87/262/320/120/92）与
   "索引↔功能"映射**就是规格**，直接继承 `config_ws2812.h` / `config_light.h`；
   逐条点亮只作为**排障工具**保留（见《从机灯带自检与排障》），不再是必经阶段；
3. **自底向上**：config → bsp → hit_detect → 状态机 → 图案 → 联调，每阶段有硬验收；
4. **时序纪律**：从机必须 **1ms 级排空 CAN**（大符轮次切换的"熄灭/点亮"两帧仅隔 150ms），
   且**禁止 `HAL_Delay` 阻塞**（老从机 200ms 阻塞是"熄灭不稳定"的根因）；
5. **⚠ 从机板未接拨码开关**（实测）：PD2/PB3/PB4 悬空 + 内部上拉 → 三个 `SW_*` 恒为高（恒"激活"），
   因此**颜色/大小符一律取 CAN 帧**（[4]/[2]），**自检只能用 `DEBUG_TEST_MODE` 宏触发**
   （拿 `SW2` 当触发会一上电就永久扫描；`TEST_TRIGGER_USE_SW2` 已置 0）。

```
S0 基线确认 ──► S1 config 从机化 ──► S2 口径继承(✅无需标定) ──► S3 bsp 适配 ──► S4 hit_detect
                                                                              │              │
                                                                              └──► S5 从机状态机 ◄──┘
                                                                                        │
                                                                                  S6 灯板图案库
                                                                                        │
                                                                                  S7 联调与验收
```

### S3 bsp 复用与适配（0.5 天）

| # | 模块 | 改动 |
|---|---|---|
| S3.1 | `bsp_can` | 逻辑复用；**把 CAN 出队从 4Hz 改到 1ms**（`bsp_can1_pop` 在 1ms 节拍里排空 → 只做"更新目标状态/置事件"），满足 150ms 熄灭间隔的时序要求 |
