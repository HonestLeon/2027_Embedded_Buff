### 0.4 主机 = 发帧遥控器（操作对照）

| 想发生的帧 | 主机操作 |
|---|---|
| 上电复位 `0x03` + 点亮第一块 `0x02` | 主机上电即自动发（约 0.5s 内两帧） |
| 红/蓝 | 主机 SW3（低=红 高=蓝）→ 下一帧起从机即时换色 |
| 小符/大符 | 主机 SW1（低=小符 高=大符）；中途切换主机会整体复位重来 |
| 击中推进/全亮 `0x04`×5 | 真击发（短接当前点亮板的 RDET），打完主机自动发全亮 |
| **熄灭旧对→点亮新对（隔 150ms）** | 大符打中第一块 → 等 1s 窗口结束自动发（组 3 核心观察点） |
| 打错复位 | 从机上报 `[2]=0x01` → 主机收报后自动复位重发（不用拨任何开关） |
| 2.5s 超时复位 | 大符第二轮起不打第二块，等 2.5s 主机自动发 `0x03` |
| SW2（停/转） | 只控电机，**不影响发帧**；台架可不接电机 |

### 0.5 击打模拟手法（避免自己制造"鬼数据"）

- 要"干净的两次击打"：**间隔 ≥300ms**（<100ms 会被去抖窗当同一击的抖动吞掉——那是预期行为，
  不是 bug，见组 2 边界表）；

## 一、组 1 · 收帧链路（对应清单 ⑥⑦⑪）

> 目标：1ms 排空 + 解析 + 本机事件锁存全链路正确。**外观先不管对错，只看"帧进得来、事件锁得住"。**

**接线**：主机 ↔ 从机（板号=1 那块）单挂 CAN1，从机接调试器。

**步骤**：

1. 从机上电（调试会话开始、跑到 `while(1)`/软 halted 都行——TIM6 调度在跑即可），
   确认 `g_sched_tick_cnt` 持续增长；
2. 主机上电 → 自动发 `0x03` + `0x02`（点亮第一块，板号大概率≠1）：
   Watch `g_buff_rx`，**帧数随主机每个动作跳增**（上电复位/点亮/熄灭/超时/全亮）；
   ⚠ 主机只在状态转换点发帧、**等待期间不发**——空闲时不涨是正常的，查的是"每个动作点都跳"；
3. 对照下表判据；异常走 §六 故障树；
4. 主机 SW1 拨大符再拨回（触发主机复位连发）→ `frames` 继续涨、`bad_frames` 恒 0；
5. 观察**全亮 5 连发**：`max_burst` 出现 **5 属正常**（一次 poll 排空 5 帧）；
   ⚠ 单板打不穿小符 5 轮（其它板没人击打 → 主机 2.5s 超时复位）——**本项顺延到组 3/组 5
   五板在线时补记**，组 1 先按"通过判据"放行；
   持续 >1 才说明排空慢（正常每拍 1~2 帧）；
6. 记下 `age_ms`：持续发帧时**稳定在 1~2**（=1ms 排空节奏，⑪ 时序判据）。

**判据**：

| 变量 | 期望 | 不满足时 |
|---|---|---|
| `g_buff_rx.frames` / `.seq` | 主机每个动作点都跳增（复位/点亮/熄灭/全亮）；空闲不涨=正常 | →§六 四步排查 |
| `g_buff_rx.bad_frames` | **恒 0**（真主机发的帧必然合法） | 有增长=接线串扰/ID 过滤器问题 |
| `g_buff_rx.age_ms` | 1~2（发帧期间）；停发后=s 秒×1000 | 恒 0xFFFF=从没收到过 |
| `g_buff_rx.my_ev_seq` | ≤frames；广播(0x03/0x04)与板号命中时 +1 | 恒 0=板号宏没对上 |
| `s_can1_rx_drop` / `s_can1_tx_drop` | **恒 0** | 看故障树第 3 步 |
| `g_dbg_slv.state` | 复位帧后 0；点亮帧板号含 1 时变 1 | 不收事件→看 my_ev |

**组 1 通过判据**：上表全绿 + 至少一次"主机发 0x02 含板号 1 → `state` 1ms 级变 1、
发 0x01/0x03 → 变 0"。记录：

| 项 | 实测 |
|---|---|
| frames 增速 / 稳态 age_ms | |
| max_burst（全亮时，**可组 3/5 补记**） | |
| bad_frames / 双向 drop | |
| ⑪ 判据 age_ms=1~2 是否成立 | ☐ |

## 三、组 3 · 状态机全流程（对应清单 ⑥⑦⑨⑩⑫；需要 **5 块板在线**，一次烧好别换）
