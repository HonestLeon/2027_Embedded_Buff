# 代码架构设计（2027 主机固件）

> 工程：`2027_Embedded_Buff/2027_Embedded_Buff_Master/`（CubeMX 已生成并核对）
> 前置文档：《主机CubeMX配置清单.md》《重构对照-旧代码与新设计.md》
> 分层原则：**Core 不手改（USER CODE 除外）、config 只放数、bsp 管硬件、application 管业务、依赖只准向下**
> 命名原则：**文件一律按外设/模块命名**——某个外设出问题，`config_<外设>.h` → `bsp_<外设>.c`
> → `application/<模块>.c` 三点一线查完，不翻别的文件。

**运行时数据流（TIM6 中断内，1ms 一次）**：

```
TIM6 1ms ─┬─ motor_update(0.001) ─┬─ 排空 bsp_can2_pop ──► motor_on_feedback
          │                       └─► bsp_can2_send(0x200 电流帧)
          ├─ bsp_ws2812_refresh_all() ──dirty&&空闲──► DMA 发送灯带
          └─ 计满 250 次（4Hz 逻辑帧）:
                bsp_switch_poll ──► 拨码状态(消抖后)
                buff_step: 排空 bsp_can1_pop(灯板回报/复位) + 读拨码
                    ├─► buff_frame_pack ──► bsp_can1_send(0x161)
                    └─► 游戏状态变化 ──► light_*(本地表现) ──► bsp_ws2812_set_rgb
                light_tick ──► 本地灯效动画 ──► bsp_ws2812_set_rgb
```

> ⚠️ 两种帧的消费节奏完全不同，不要混淆：
> **电机反馈每 1ms 排空一次**（TIM6 中断里 motor_update 开头 while 排空
> `bsp_can2_pop`，1kHz×4 帧/ms 的到达速率绝不能等 250ms）；
> **从机帧才在 4Hz 逻辑帧里排空**（`bsp_can1_pop`，一秒几帧，250ms 完全够）。
> 250ms 逻辑帧与 CAN2 电机队列无关。

## 二、依赖规则（必须遵守，code review 按此检查）

| 层 | 可以 include | 严禁 |
|---|---|---|
| `config/` | 什么都可以不 include（只被别人 include） | include 任何 .c 层的东西；只有 `#define` / `const` 表 |
| `bsp/` | HAL 句柄、`config/*` | 出现业务概念（"环数""大符""第几轮"）；阻塞等中断 |
| `application/` | `bsp/*`、`config/*`、同层互相 | 直接操作寄存器/CCR 数组；自己写 while 死等 |
| `Core/` USER CODE | 只调各模块 `xxx_init()` + 调度器 | 出现其他业务代码 |

**调度进中断后的四条纪律**（TIM6 中断现在跑业务，必须守住）：

1. 中断里调用的所有函数**非阻塞**——禁止 `HAL_Delay`、禁止死等邮箱/标志位
   （bsp_can1/2_send 为"查一次邮箱、满即丢"零等待设计，bsp_ws2812_refresh_all
   只在空闲时启动）；
2. **发送/接收只在 TIM6 中断上下文**——FreeLevel 查询与 AddTxMessage 非原子，
   主循环和中断同时调 bsp_can1/2_send 会撞车，架构上禁止 main 循环发 CAN；
3. **主循环保持为空**——bsp_ws2812 刷新只在中断里做，避免"主循环和中断同时
   Start_DMA"的并发竞争（这是把刷新搬进中断的原因，不只是省事）；
4. 优先级次序保证抢占安全：CAN RX（1）可抢占 TIM6（2），
   TIM6 可抢占 DMA 完成回调（5）；中断耗时预算：1ms 节拍内
   电机 PID（<50µs）+ 单条灯带翻译（<0.2ms）+ 4Hz 帧任务（偶发）。
   ⚠ 最坏情况: 6 条灯带同帧全 dirty 时翻译总量可达 ~0.6~1.2ms，可能吃满节拍——
   实现 refresh_all 时每 tick 最多启动 2 条，剩余下个 tick 继续（帧周期余量足够）。

### 3.2 bsp/（4 个模块）

**`bsp_can.h / .c`**

| 函数 | 职责 | 对应老代码 |
|---|---|---|
| `void bsp_can_init(void)` | CAN1/CAN2 各配 MASK 过滤器 + `HAL_CAN_Start` + `ActivateNotification(RX_FIFO0)` | 老 `can_filter_init()`（IDLIST 硬编码 → MASK） |
| `bool bsp_can1_send(uint32_t id, const uint8_t data[8])` | **CAN1(从机总线)**：查一次空邮箱，满→丢弃+计数立即返回（**零等待**，原因见上）；空→`AddTxMessage` 入邮箱立即返回，硬件异步发送 | 老 `CanSend()` 死等循环+被注释的超时 |
| `bool bsp_can2_send(uint32_t id, const uint8_t data[8])` | **CAN2(电机总线)**：同上 | 老 `CAN_Motor_Send1()` |
| `bool bsp_can1_pop(uint32_t *id, uint8_t data[8])` | 从**从机帧队列**(0x160/0x161)取一帧，空返回 false → `buff.c` 4Hz 消费 | 老"中断直接 memcpy 进全局数组" |
| `bool bsp_can2_pop(uint32_t *id, uint8_t data[8])` | 从**电机反馈队列**(0x201~0x204)取一帧 → `motor.c` 1ms 排空 | 同上 |
| `uint32_t bsp_can1/2_tx_drop_count(void)` | 各总线**发送**失败计数（邮箱满即丢） | 无（新增） |
| `uint32_t bsp_can1/2_rx_drop_count(void)` | 各总线**接收**队列溢出计数 | 无（新增） |
| `HAL_CAN_RxFifo0MsgPendingCallback`（内部） | `GetRxMessage` 后**按 hcan 分发到对应总线队列**，3 行 | 老回调里做业务 → 收编 |

内部：**两条总线各自独立队列**（长度在 `config_can.h`：CAN1=16 帧——从机帧 4Hz；
CAN2=32 帧——电机反馈 1kHz×4 ID ≈ 4 帧/ms，1ms 排空一次最多积 4 帧，留 8 倍裕量），
单生产单消费无锁（ISR 写 / 任务读），长度为 2 的幂以便位与取模。
过滤器为 32 位 MASK 模式：CAN1 用 bank0、CAN2 用 bank14（≥ `SlaveStartFilterBank`）。
⚠ `bsp_can_init` 时 CAN2 的 FilterBank 编号必须 ≥ `SlaveStartFilterBank`(=14，
CAN1 占 bank 0~13)——CAN1 用 bank0、CAN2 用 bank14，否则 CAN2 过滤器不生效。
> 注意 bsp 层只用 **CAN1/CAN2 硬件名**命名，不出现 buff/motor 业务词；
> "CAN1=从机、CAN2=电机"的对应关系由 application 侧使用方式体现。

|---|---|---|

| `void bsp_ws2812_set_rgb(uint8_t strip, uint16_t start, uint16_t count, uint8_t r,g,b)` | 写 rgb 逻辑缓冲 + 置 dirty | 老 `WS_2812_Set_RGB` |
| `void bsp_ws2812_fill(uint8_t strip, uint8_t r,g,b)` | 整条填充 | 老反复 Set_RGB 清屏 |
| `void bsp_ws2812_refresh_all(void)` | 每条：`!busy && dirty` → 翻译+Start_DMA+busy=1（**TIM6 中断里调**；每 tick 最多启动 2 条防 ISR 超时） | 老每圈无条件 Start_DMA ×5 |
| `HAL_TIM_PWM_PulseFinishedCallback`（内部） | 按 `htim->Channel` 定位是哪条灯带发完（⚠ 同一定时器挂多条灯带，只匹配 htim 不够）→ **只清 busy=0，无需 Stop_DMA**：HAL 在 Normal 模式下于回调前已自动复位通道状态（已核对本工程 hal_tim.c 源码）；DMABurstState 属于 DMABurst_Read/Write API，与 PWM Start_DMA 路径无关 | 无（新增，根治重启撞车） |
| `static ws2812_translate()` | RGB→CCR 逐位查表 `bit_ccr[2]={T0H,T1H}`，GRB 高位先行 | 老 `WS_2812_Set_RGB` 算法原样 |

> `ch_idx` 字段定义：通道序号的 ACTIVE 编码（0x01/0x02/0x04/0x08），init 时由
> `ch_idx = 1u << (channel >> 2)` 换算，与 `htim->Channel`（`HAL_TIM_ACTIVE_CHANNEL_x`，
> 见本工程 hal_tim.h L324~328）**直接相等比较**。⚠ 不是 `(channel>>2)+1`：
> ACTIVE_CHANNEL_3=0x04、_4=0x08 是位掩码式编码，CH3/CH4 会匹配失败。

### 3.3 application/（3 个模块）

**`motor.h / .c`** —— 电机

```c
void motor_init(void);                  /* PID 参数装载(MOTOR_*宏) */
void motor_set_run(bool run);           /* SW_RUN 拨码 → 目标是否推进 */
void motor_set_mode(bool big);          /* 大/小符 */
void motor_update(float dt);            /* 1ms(TIM6中断): 先排空 bsp_can2_pop 喂
                                           motor_on_feedback(解析0x201~204);
                                           正弦目标+前馈+双环PID+过零累计
                                           → 电流限幅 → bsp_can2_send(0x200) */
void motor_on_feedback(uint32_t id, const uint8_t raw[8]); /* 单帧解析: 0x201~0x204(老MotorReceive逻辑) */
```

老 `motor_control()` 的正弦目标、前馈、级联 PID、`Zero_Check` 过零、0x200 帧格式
**全部原样保留**；老 `Motor1_Pid` 死变量删除。
实现细节差异(3 处, 已写明在 motor.h)：①`dt` 由 TIM6 节拍给定恒定 0.001（老代码靠 DWT
实测补偿主循环抖动）；②反馈统一走 `bsp_can2_pop`（老代码在 CAN 中断里解析）；
③老的 `ChassisMotorCanReceive[i]` 里 `i` 是全局变量(恰好为 0 才取到电机0)，这里显式用索引 0。
三角函数用标准 `sinf/cosf`（老代码用 CMSIS-DSP，新 Keil 工程未链接该库；1kHz 调两次差异可忽略）。
拨码接线：4Hz 帧里 `motor_set_run(sw_run)` / `motor_set_mode(sw_buff)`。

**`buff.h / .c`** —— 从机灯板业务（协议 + 状态机 + 随机，单文件全并）

```c
/* ── 协议(主从共用语义, 从机工程复制本段) ── */
typedef enum { BF_EXTINGUISH=0x01, BF_LIGHT=0x02, BF_RESET=0x03, BF_ALL_ON=0x04 } bf_cmd_t;
typedef struct {
    bf_cmd_t cmd; uint8_t is_big; uint8_t panel_a;   /* 1~5, 0=无 */
    uint8_t panel_b;                                  /* 大符第二块, 0=无 */
    uint8_t is_blue; uint8_t round;                   /* 大符第几轮 0~5 */
} buff_frame_t;
uint8_t buff_frame_pack(uint8_t out[8], const buff_frame_t *f);   /* 恒返回8 */
bool   buff_frame_parse(const uint8_t in[8], buff_frame_t *f);   /* 校验包头0xaa */
/* 字节语义=老协议注释: [0]=0xaa [1]=cmd [2]=大小符 [3]=panel_a
   [4]=红蓝 [5]=panel_b [6]=round */

/* ── 状态机 ── */
typedef enum { BB_RESET, BB_IDLE, BB_LIT, BB_HIT_WINDOW, BB_COOLDOWN, BB_ALL_ON } bb_state_t;
void buff_init(void);          /* 取随机序列, 清计数 */
void buff_step(void);          /* 4Hz: 排空 bsp_can1_pop + 拨码变化 → 转换/发帧 */
void buff_tick(float dt);      /* 1ms: 2.5s超时 / 1s窗口 计时 */

/* 内部: bb_state_t state; uint8_t round; small_seq[5]; big_a[5], big_b[5];
   随机生成: 不重复规则同老代码(小符5个不重复; 大符前后轮可重复、同轮b[i]≠a[i]);
   ⚠ 老函数内部的 srand(CNT_my)/srand(random_seed) 必须移除——CNT_my 无人递增、
   TIM2 已删; 种子统一由上电 bsp_rng_get_seed 注入, 函数只做纯生成 */
```

**从机回报解析（`buff_slave_report_parse`）**：老协议两个方向共用同一帧结构，
从机回报里 `[1]==0x03` = 被击中（`[3]` = 灯板号），`[2]==0x01` = 打错复位。
⚠ **复位优先判定**：从机的复位帧里 `[1]` 会残留上一次的 `0x03`（`send_to_chassis_data`
是全局数组，只改了 `[2]`），若按 `[1]` 先判会把复位误判成击中。

**与老代码的 3 处有意修正**（已核实并记录）：
1. 老小符分支 `if (finish_flag && counter <= 5) ... num[counter]` 在 `counter==5` 时
   **越界读 `num[5]`**（实际读到相邻数组 `num2[0]`）→ 小符实际需要点亮/击中 **6 次**才全亮；
   新实现按规则只做 **5 次**。
2. **大符轮次切换的"熄灭"真正生效了**（老代码形同虚设）：
   规则要求"重新点亮前灯效熄灭至多 200ms"；主机在该间隔内要发两帧（先 `0x01` 熄灭旧对、
   再 `0x02` 点亮新对），**从机必须两帧都收到**才能熄灭旧对。
   - 老代码：两帧相隔 ≈1ms，而老从机是"单缓冲 + 200ms 主循环" → 只看到后一帧 →
     **熄灭帧被吞，旧对不熄**（2025 实机就这表现，只是被击中那块的环数显示掩盖了）；
   - 新实现：`BUFF_EXTINGUISH_GAP_MS = 150ms`（≤ 规则上限 200ms，留裕量且肉眼可见），
     熄灭帧显式携带当前对的 `panel_a/panel_b`（老代码这两个字段是注释掉的，靠残留字节指代）。
   - **对从机的硬性要求**：必须及时处理 CAN（建议 1ms 排空队列），否则 150ms 内的两帧仍会被吞。
3. 中途切换 SW1（大小符）→ 新实现直接复位重来（老代码会拿新模式的变量去接旧计数，属缺陷）。

**刻意保留的老行为**：第一块灯板点亮后**不设超时**（必须被击中才继续）；大符首击后 1s 窗口
才熄灭旧对；从机回报的"打错复位"可打断任意状态。

状态转换表（设计即注释）：

```
BB_RESET ──发全复位帧──► BB_IDLE
BB_IDLE  ──4Hz且counter==0──► 点亮(num2[0],num3[0]) ──► BB_LIT
BB_LIT   ──收到"被点亮"回报──► (小符)点亮下一块 / (大符)──► BB_HIT_WINDOW
BB_LIT   ──2.5s无回报──► BB_RESET
BB_HIT_WINDOW ──1s内收到回报或超时──► BB_COOLDOWN
BB_LIT   ──小符第5块回报──► 发ALL_ON ──► BB_ALL_ON
BB_ALL_ON ──2.5s后──► BB_RESET (老行为: 全亮展示后超时复位)
```

**`light.h / .c`** —— 主机板载灯带灯效

### 3.4 从机构建的分层映射（同一框架，只换业务层）

主机与从机共用同一套 `config / bsp` 框架，**从机只换 application 层**（详见
`docs/从机代码重构计划.md` 第六节"可复用资产清单"）：

| 层 | 主机（中心板） | 从机（打符灯板） |
|---|---|---|
| `config/` | 6 个头文件 | 同一套，**删 `config_motor.h`**；`config_board.h` 的 `BOARD_ROLE_MASTER=0` + `SLAVE_PANEL_NUM`(1~5) |
| `bsp/` | ws2812 / can / switch / rng | **完全相同（直接复用）**；仅 CAN 排空节奏放 1ms |
| `application/` | `motor` + `buff`(大小符状态机) + `light`(本地灯带) | `buff`(换成**从机状态机**) + `light`(**灯板图案库**) + **`hit_detect`(新增)** |
| 调度 | 1ms：电机环 + 灯带刷新；4Hz：拨码/状态机/灯效 | 1ms：**CAN 排空** + 灯带刷新；4Hz：状态机/图案 |
| 协议 | `buff.c` 的协议段 | **逐字节相同**（主从共享的唯一真相源） |
| 角色专用 | 不编 `hit_detect.c` | 不编 `motor.c`（各自 Keil Group 里排除） |

## 四、与 CubeMX 工程的集成方式

1. **文件夹位置**：`config/ bsp/ application/` 建在工程根（与 `Core/` 平级）。
   CubeMX 重新生成**不会删除**它们；
2. **Keil 接入**（一次性手工操作）：
   - `Project → Manage Project Items`：新建 Groups `bsp / application`，加 7 个 .c；
   - `Options → C/C++ → Include Paths`：追加 `..\config;..\bsp;..\application`；
3. **main.c 挂钩**（USER CODE 区域，只有初始化）：

```c
/* USER CODE BEGIN 2 */
HAL_Delay(100);                 /* 等 WS2812 供电稳 */
bsp_ws2812_init();
bsp_switch_init();
bsp_can_init();
srand(bsp_rng_get_seed());
motor_init();
buff_init();
light_init();
HAL_TIM_Base_Start_IT(&htim6);  /* ★ 必须最后一句: 中断一启动就跑 motor_update,
                                   放在 init 之前会用未初始化参数跑 1~2 个 tick
                                   (现工程 main.c 里这行在 bsp_can_init 之后, 请挪到这里) */
/* USER CODE END 2 */

/* USER CODE BEGIN WHILE */
while (1) {
    __WFI();                    /* 空转等中断, 调度全在 TIM6 */
/* USER CODE END WHILE */
```

4. **调度器入口**（`Core/Src/stm32f4xx_it.c` USER CODE 1，**已写好**）：

```c
/* USER CODE BEGIN 1 */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim)
{
  if (htim == &htim6)
  {
    // TIM6 中断处理调度逻辑（1ms: motor_update / bsp_ws2812_refresh_all;
    //                    250 分频: 逻辑帧）
  }
}
/* USER CODE END 1 */
```

- 走 `HAL_TIM_PeriodElapsedCallback` 而不是直接在 `TIM6_DAC_IRQHandler` 里写逻辑是
  正确做法：中断入口由 CubeMX 生成的 Handler 统一调 HAL，回调按句柄分发；
- `if (htim == &htim6)` 必须保留——该回调是所有定时器的公共入口，将来任何定时器
  开了更新中断都会进这里；
- `HAL_TIM_Base_Start_IT(&htim6)` 已在 main.c USER CODE 2 调用 ✓（没有它回调不会触发）；
- 调度逻辑直接写在回调内（it.c USER CODE 1），不另建文件；
  建议拆两个小函数（`sched_1ms()` / `sched_frame()`）放 application 层供它调用，
  保持 it.c 轻薄（可选，不强求）。

5. **中断回调归属**（避免重复定义）：
   - `HAL_TIM_PeriodElapsedCallback`（TIM6）→ **it.c USER CODE 1（已就位）**
   - `HAL_TIM_PWM_PulseFinishedCallback`（WS2812 DMA）→ `bsp_ws2812.c`
   - `HAL_CAN_RxFifo0MsgPendingCallback` → `bsp_can.c`
   - 电机反馈帧 0x201~0x204：`motor_update` 排空 `bsp_can2_pop` 后调 `motor_on_feedback` 解析（1ms 节奏，见 3.3），不经 4Hz 逻辑帧

## 五、约定与遗留项

- **命名**：文件与函数一律按外设/模块命名——`config_<外设>.h`、`bsp_<外设>.c`、
  `application/<模块>.c`，函数前缀=所在模块（`motor_` / `buff_` / `light_` / `bsp_can_`...），
  类型 `_t`，宏全大写；
- **角色划分**：`buff`=从机灯板（CAN 指挥）、`light`=主机板载灯带（本地驱动），
  从机工程将来复用 `config_board.h(改0)` + `buff.c` 的协议段 + 新增 `hit_detect.c`；
- 合并记录：老 `buff_fsm/protocol/random/pattern` 四件套 → `buff.c` 单文件；
  config 定稿 6 个（board/can/ws2812/motor/buff/light）；
- 遗留待确认（不阻塞编码）：U15 中心屏接口
  （确认后加 `bsp_center.c`）、拨码极性（`config_board.h` 回填）、CAN 波特率（CAN 盒实测）；
- 《重构对照》第 9 节 12 项标定核对表 = config 文件填充完成标准。
